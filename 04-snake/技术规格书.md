# 04-snake — 技术规格书

> 依据：`04-snake/策划案.md`。结构样板沿用 pingpong / space-invaders / pacman（DECISION_LOG 010）。与实现冲突时修正实现。

## 1. 运行与返回

- 编号 04，slug `snake`，目录 `04-snake`，主场景 `snake.tscn`（游戏根，符合主场景契约）。
- 只从 hub 桌面进入；`Esc` 调 `GameRouter.back_to_hub()`。
- 逻辑分辨率固定 1280×720（`canvas_items + keep`，DECISION_LOG 017）。Node2D 坐标 == 逻辑像素坐标（根无 transform）。

## 3. 结构模型（场景即架构，CONSTITUTION 五点五）

```
snake.tscn  (Snake, Control, game.gd)
├─ Background (ColorRect)
├─ Board (Node2D, snake_board.gd)      ← 面板/网格线/边框/调试标记，自绘
├─ Playfield (Node2D)
│   ├─ Body (Node2D, snake_body.gd)    ← 蛇身节段池 + 格子数据
│   └─ FoodSlot (Node2D)               ← food.tscn 实例挂点
├─ Hud (Control, snake_hud.gd)
│   ├─ ScoreLabel / ScoreValue
│   ├─ LevelLabel / LevelValue
│   ├─ LengthLabel / LengthValue
│   └─ BestLabel / BestValue
├─ Overlay > Message (Label)
└─ Audio (Node, snake_audio.gd)
```

- **静态结构**（面板、网格、UI 骨架、挂点）全部写在 `.tscn`。
- **动态内容**（蛇身节段、食物）由代码 `instantiate()` 后挂进场景预留的 `Body` / `FoodSlot`。
- 面板是**空网格**、非关卡地图，网格线属渲染细节，用 `SnakeBoard._draw()` 绘制（与 pacman 的 `PacmanPellets` 自绘层同一做法），不引入 TileMap/TileSet。
- 节点访问一律 `@onready var _x: Type = $Path`（CONSTITUTION 五）。

## 4. 几何（`snake_grid.gd`，`class_name SnakeGrid`）

静态几何，全部由 `configure(cell_size, cols, rows)` 在启动时算定：

- `CELL × COLS × ROWS`，默认 `40 × 30 × 15` → 面板 1200×600。
- `ORIGIN = (FIELD − BOARD_SIZE) / 2` = `(40, 60)`：左右各留 40px、上下各留 60px，**顶部 60px 即 HUD 信息带**。
- `FIELD = (1280, 720)`，与 `SpaceField.SIZE` / `PacmanGrid.FIELD` 一致。
- 提供 `cell_center` / `in_bounds` / `wrap` / `index` / `DIR_*` / `dir_name`。

## 6. 蛇身（`snake_body.gd`，`class_name SnakeBody`）

- 数据：`_cells: Array[Vector2i]`（**下标 0 = 头**）、`_direction`、`_desired`、`_grow_pending`。
- 渲染：`_segments: Array[SnakeSegment]` 池，节点挂在 `Body` 下，每步只改 `position` 与颜色，不反复建销。节段超出当前长度则 `visible = false`。
- **接口**：
  - `configure(side, inset, body_color, head_color, dead_color, wrap)` — 尺寸与配色。
  - `reset(cells, dir)` — 重开。
  - `queue_direction(dir)` — 记录转向意图；**与当前方向相反的立即丢弃**（禁 180° 掉头）。
  - `advance() -> bool` — 走一格，返回是否存活；死因读 `death_reason`（`Death .WALL / .SELF`）。
  - `grow(count)` / `set_dead_tint(enabled)` — 增长与死亡染色。
  - `head_cell()` / `cells()` / `length()` / `direction()` / `occupies(cell)` — 状态查询。
  - `step_target(dir)` / `would_die_entering(cell)` — 供调试标记复用，**与真实判定同一套规则**。
  - **蛇不知道食物与分数**：吃没吃到由 `game.gd` 比较 `head_cell()` 与食物格决定，再调 `grow()`。
- **一步的判定顺序**：
  1. 应用 `_desired`（合法才生效）。
  2. 算 `next = head + _direction`；若 `wrap_edges` 则 `wrap(next)`，否则越界即 **WALL 死**。
  3. 自咬：`next` 命中身体即 **SELF 死**——**但尾巴格豁免**：若本步不增长（`_grow_pending == 0`）且 `next` 恰为最后一节，则允许。
  4. 头插 `next`；若 `_grow_pending > 0` 则 `_grow_pending -= 1`，否则 `pop_back()`。
- **死亡顺序**：先判死、后位移——若死则不发 `ate`、不增长。
- `set_dead_tint()` — 死亡时把全身改成 `dead_color`（视觉反馈，约 0.6s）。

## 7. 食物（`snake_food.gd`，`class_name SnakeFood`）

- 由 `game.gd` 选格 → `FoodSlot` 里 `instantiate()` 一个 `food.tscn` → `place(cell)`。
- `_process` 做呼吸脉冲：`scale = lerp(pulse_min, 1.0, 0.5 + 0.5*sin(t*pulse_speed))`。
- 选格算法：遍历全部格子收集**未被蛇占据**的空格，随机取一个；**空格为空 = 通关**（`game.gd` 显示胜利）。

## 8. 对局（`game.gd`，`class_name SnakeGame`）

- 状态机 `State { READY, PLAYING, DEAD, GAME_OVER, WIN }`。
- 启动：`configure` 几何 → 建蛇（居中横排 `start_length` 节，朝 `start_dir`）→ 放第一个食物 → `READY` 覆盖 1.2s → `PLAYING`。
- `PLAYING` 每帧：
  - 转向走 **`_unhandled_input` 事件**（不是逐帧轮询）——同一帧内先后按两个方向键时保留**按键顺序**，轮询会把它们塌成固定优先级。
  - `_step_timer += delta`；到 `_interval()` 则 `advance()`；存活则刷新长度与调试标记。
- `_interval()`：`max(min_interval, base_interval − (min(level, level_cap) − 1) * interval_step)`。
- 吃食：`advance()` 后比较 `body.head_cell()` 与食物格；命中则加分、`body.grow(growth_per_food)`、音效与计数；`foods_eaten % foods_per_level == 0` → `level += 1`（封顶）并播升级音；再放新食物。
  - **增长在下一步才落地**：`grow()` 只累加待增长数，下一步 `advance()` 时头进而不弹尾，长度才 +1。故 HUD 的 `LENGTH` 如实滞后一步，不虚报。
- 死亡：进 `DEAD`，`body.set_dead_tint()`，0.6s 后 `GAME_OVER`，显示 `GAME OVER\nPRESS SPACE`。
- `GAME_OVER` / `WIN` 时按 `fire`（空格）重开。

## 9. 调试键与作弊键

### 9.1 调试键（`debug_toggle` = `P`）——只读

- 只读可视化：开启后 `SnakeBoard` 在蛇头**紧邻的三个非反向格**上画标记——**红 = 会死（墙/身体）、绿 = 安全**（网格线本就常显，不属调试专属）。
- `game.gd` 在每次 `advance()` 后重算标记并推给 `_board`；**不改变任何玩法逻辑**，观察到的即真实判定。

### 9.2 作弊键（`cheat_toggle` = `C`）——穿墙

- 动作 `cheat_toggle` 为**项目级输入映射**（与 `debug_toggle` 平行，供后续游戏复用），本作绑定 `C`。
- 效果：打开 `SnakeBody.wrap_edges`，蛇走出边界后从对面回来而非死。
- **层叠而非覆盖**：`body.wrap_edges = cfg.snake.wrap_edges or 作弊位`——设计者在 cfg 里开了穿墙也不会被作弊键关掉。
- **双重视觉反馈**：① 边框改用 `border_color_cheat`（边框即"死亡面"，不再致命就该变样）；② 短暂覆盖文字 `WALL PASS ON / OFF`（0.9s）。
- **调试标记自动跟随**：`step_target` / `would_die_entering` 本就读 `wrap_edges`，所以开启后头旁的越界格会立刻从红变绿，**可视化与真实判定始终一致**。
- **每次开局复位为关**：`_start_run()` 清 `_cheat_wrap` 并重算——新一局永远按真实规则起手，不留隐形残留。

## 10. 程序化音频（`snake_audio.gd`，`class_name SnakeAudio`）

沿用 02/03 范式：启动合成 PCM 到 `AudioStreamWAV`（22.05kHz / 16-bit / 单声道），`AudioStreamPlayer` 池播放。

| 事件 | 音色方向 |
| --- | --- |
| 吃食 | 方波双音交替 620↔880Hz / 0.06s，每次交替 |
| 升级 | 上行三音 `[523, 659, 784]` |
| 死亡 | 下行 `[520, 400, 300, 200]` |
| 开局 | 低音一声 300Hz / 0.10s |

`SnakeBody` 不引用音频：`game.gd` 依据 `advance()` 的返回值与食物格比较结果，自行调用 `SnakeAudio` 的对应方法（与 01 的 `scored` 同模式）。

### 10.1 循环背景音乐（`_build_music()`）

同样是启动时合成，同样零素材：

- **音乐结构**：C 大调 / 4/4 / **128 BPM / 4 小节 = 32 个八分音符 ≈ 7.5 秒**；和弦走 **I–IV–V–I（C–F–G–C）**，末小节收在主音上，接回开头无缝。
- **两个声部**：方波主旋律（`MELODY`）+ 三角波低音（`BASS`，根音在正拍、高八度在反拍，形成"蓬-恰"跳动感）。每个音走「快起音 → 衰减到 0.55 → 尾部释放」的包络。
- **音符表就是可读的调参面**：`MELODY` / `BASS` 是 `[midi 音高, 八分音符长度]` 的数组（`0` = 休止），改这里就能改旋律。
- **循环**：`AudioStreamWAV.loop_mode = LOOP_FORWARD`，`loop_begin = 0`、`loop_end` 铺满整个缓冲。首尾样本都落在包络的零点上（实测 `head=0.0000`、`tail=0.0001`），**接缝无爆音**。
- **播放**：专用 `AudioStreamPlayer`（`MUSIC_VOLUME_DB = -10.0`）常驻循环。**开局 `play_music()`、死亡 `stop_music()`**（让死亡音效落在一片安静里），重开再起。
- **唯一需要按耳朵定的旋钮**：`MUSIC_VOLUME_DB`（混音峰值约 0.52，此值让音乐明显低于音效之下）。

## 11. 输入

复用项目级 `[input]`（`project.godot` 已定义）：`wasd_up/down/left/right`、`arrow_up/down/left/right`、`fire`（空格）、`debug_toggle`（`P`）、`cheat_toggle`（`C`）、`ui_cancel`（Esc）。

其中 `cheat_toggle` 由本作立项时新增（DECISION_LOG 023），与 `debug_toggle` 一样是**项目级、跨游戏共用**的键位。

## 12. 风险 / TODO

| 事项 | 优先级 | 说明 |
| --- | --- | --- |
| 高速下的输入容错 | 中 | 间隔最短 0.06s，需实机确认"连按两键在一个 step 内"不会吞掉最后一次意图（队列只保留最新合法方向） |
| 自咬豁免的边界 | 中 | "头进尾格"豁免只在**不增长**时成立；已有断言覆盖，实机再回归一次 |
| 音乐与音效的音量平衡 | 中 | 本环境无声卡，只能保证不静音/不削波；`MUSIC_VOLUME_DB` 需按耳朵定 |
| 最高分不持久化 | 低 | 策划案已声明仅会话内；如需持久化另开条目 |
| 蛇头朝向指示 | 低 | 当前只靠颜色区分头身，如需再加眼睛 |

## 13. 验收

### 已跑过的

- `godot --headless --path . --import`：无 error / warning。
- `godot --headless --path . res://04-snake/snake.tscn --quit`：场景可加载，无脚本错误（该命令下与 03-pacman 同样只报 `AudioStreamWAV` / `AudioStreamPlaybackWAV` 两个既有泄漏，非本游戏引入）。
- **核心规则断言（23 项全过）**：一次性 headless 脚本驱动 `SnakeBody`，覆盖基础步进、垂直转向、禁 180° 掉头、撞墙死、自咬死、**头进尾格豁免**、**增长时同一格不再豁免**、增长落地、穿墙、`would_die_entering` 一致性、`SnakeBoard` 标记绘制。脚本用完即删（本仓库无测试框架，属一次性验证，见 DECISION_LOG 021）。
- **作弊键与音乐断言（16 项全过）**：`C` 开局为关、按下后 `wrap_edges` 置真且边框进入变暗态、**越界不再致命**、再按恢复致命、**重开一局自动复位**；音乐缓冲 `frames=165375`（=7.5s）、`LOOP_FORWARD` 且 `loop_end` 铺满、`peak=0.518`（不削波且可闻）、`rms=0.199`（不静音）、首尾样本 `0.0000 / 0.0001`（接缝无爆音）。
- **画面实拍**：真实窗口下让程序自己 `save_png` 到 `user://` 后读图，确认 READY / PLAYING / GAME OVER 三态布局、HUD 信息带、棋盘边框与网格、死亡染色，以及**作弊开启后边框变暗 + `WALL PASS ON` 提示**都对。

### 仍待手测（只有人能定）

- 手感：`base_interval 0.16` 与 `interval_step 0.012` 是否顺手、转向是否跟手。
- **听感**：音效与 BGM 的实际听感（本环境无声卡，只能验证"有声音、不削波、循环无爆音"这些可测的部分）；`MUSIC_VOLUME_DB` 与两张音符表是唯一需要按耳朵调的地方。
