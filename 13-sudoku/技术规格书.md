## 3. 结构模型（场景即架构，CONSTITUTION 五点五）

```

├─ ScreenHolder (Node)                     三屏整屏替换
├─ Audio (Node, sudoku_audio.gd)
```

**`InputTranslator` 挂在根而不是对局屏**：三个键位动作到本作语义的翻译是全局的，注册一次比每屏注册注销一次少一处能出错的地方。

```
scenes/play.tscn  (Play, Control, sudoku_play.gd)
├─ Backdrop (ColorRect)
├─ Board (Control, sudoku_view.gd)     81 个格子由代码生成
├─ Hud (Control, sudoku_hud.gd)        顶栏读数与底栏提示
├─ Overlay (Control, sudoku_debug.gd)  P 叠加层，默认关
└─ PauseHolder (Node)                  暂停菜单挂这里
```

### 3.1 ★ 81 个格子由代码生成，不是场景里的固定结构

2048 的 16 个格子是写死在场景里的——16 组 `Panel + Label` 还读得下去。数独不行：**81 个格子，每个要显示 1 个大数字或 9 个铅笔小数字**，写进场景文件就是 800 多个节点，没人能读、也没人敢改。

所以 `SudokuView.setup()` 建 81 个 `SudokuCell`，绝对定位（`index` 决定行列），每个格子**自己在 `_draw()` 里画**：

- **一个 `Control` 一次 `_draw`**，不是 9 个 `Label`。一个格子要在大数字和 3×3 小数字之间切换，9 个常驻 `Label` 就是 729 个节点，且引擎每次刷新都要重新解算它们的布局。
- **网格线由格子自己画**（每条边由它右下方的格子画），所以线在**高亮底色之上**——父节点先画、子节点后画，如果把线交给父节点画就会被光标格的底色盖住。粗线（宫界）3px、细线 1px。
- 格子只认一个 state 字典（`set_state`），**不知道棋盘的存在**；view 负责把棋盘翻译成 81 份状态。

## 4. 数据模型（`sudoku_board.gd`，`class_name SudokuBoard`）

**纯逻辑，`extends RefCounted`**——不碰场景树、不发信号，所以断言可以直接驱动它（本作断言的重头）。

- 三份 81 长数组：`given`（题目给的，**开局写入后永不改动**）、`values`（当前盘面）、`notes`（铅笔位掩码）。
- **`ALL_DIGITS := 0x3FE`**——每个数字占一位，数字 d 用 bit d，所以掩码覆盖 bit 1..9，**bit 0 永远不用**。⚠️ 看着更顺眼的 `0x1FF`（bit 0..8）是错的，见 §11 第 1 条。
- `place()` / `erase()` / `toggle_note()` **在给定格上一律拒绝并返回 false**——给定格不可改是这一款唯一的硬规则，也是"谁写的"这件事的唯一记录。
- `used_mask(index)` → 同行、同列、同宫已出现的数字并成一个掩码；`candidates_at()` = `ALL_DIGITS & ~used_mask`；`candidate_count()`。
- `conflicts()`：**只报"盘面自相矛盾"**——一行/列/宫里同一个数字出现第二次，把**所有**持该数字的格标 1。它**从不查答案**，所以一个填错但暂时不重复的数字是安静的（§5.3）。
- `is_complete()`：81 格填满**且**无冲突。**不是"等于生成器的答案"**——那会把另一个合法解判成错的。

## 5. 生成器（`sudoku_generator.gd`，`class_name SudokuGenerator`）

### 5.1 两件事

1. **`full_solution(rng)`**：空盘上用"最少候选格优先 + 候选随机排序"的回溯填满。**1 ms 量级**。
2. **`count_solutions(grid, limit)`**：数解的个数，数到 `limit` 就停。`limit = 2` 回答的是"是否唯一"，**永远不需要知道真实个数**。
3. **`generate(rng, target_blanks)`**：造终盘 → 随机顺序逐格挖 → **每挖一格验一次唯一解**，验不过就把那一格填回去。

### 5.2 `target_blanks` 是**上限，不是承诺**

唯一解是硬约束，它赢。挖到目标空格数就停，或者 81 格试完就停，**两者取先到**。所以一局**永远不会比要求更难**，偶尔会略简单——这是诚实的行为，另一条路是发一张有两个答案的盘。

三档（`sudoku.cfg`）：EASY 40 / NORMAL 48 / HARD 52 个空格。**实测三档全部挖满目标**（10 局平均：40 / 48 / 52），单局 3.2 / 5.3 / 8.7 ms。

### 5.3 不查答案的冲突

`conflicts()` 只做"同一单元内有无重复"这一件事。**这是刻意的**：查答案等于把"你这个数是错的"直接告诉玩家，那是另一种作弊键。填错但不冲突的数字保持安静，玩家自己承担判断——这也是为什么 `[` 和 `]` 两个作弊键有意义。

## 6. 对局（`sudoku_play.gd`，`class_name SudokuPlay`）

- 状态：`_finished` 一个标志位。结算由 root 接手切屏，所以对局屏不需要自己的状态机。
- **计时**：`_process` 累加 `_elapsed_ms`，暂停时 `_process` 自动停（`process_mode` 是默认的 `INHERIT`）。**HUD 只在秒数变化时重绘**——时钟的可见位数变了才值得重画，其余靠输入驱动。
- **填入**：给定格 → 响一声冲突音并拒绝；铅笔模式 → 翻转标记；否则写入。写入后**自己造成的冲突**计一次错误并奏冲突音，否则按数字高低奏一个音。
- **通关**：`is_complete()` 为真 → 发 `solved(elapsed_ms, mistakes)`，root 决定这条成绩值不值得存档。

### 6.1 超级作弊 `]`（`super_cheat_toggle`）

**光标落到的空格，立刻填上正确答案**，并在 `_auto_filled` 里标记。

- 它破坏的是"你得自己想出来"这条约束——**填格这件事本身一点没省**：光标照样要一格一格移过去，盘面照样要填满，照样要合法。
- **绿色标记持久**：被 `]` 填过的格子带 `#00E676` 标记，**关掉作弊也还认得出是谁写的**；玩家自己擦掉重填则标记消失。颜色画在"被接管的那样东西"（那个数字）上（CONSTITUTION 八）。
- **触发点是"光标落到"而不是"按键那一刻"**：所以开着它移动光标，一路扫过去的空格会自己填好。

### 6.2 作弊键 `[`（`cheat_toggle`）

**把所有空格的候选数显示出来**（青色）。等价于把铅笔工作全部代劳——排除法不再需要玩家自己算。**只影响画面，不改盘面**：关掉即恢复，且不写入 `notes`。

## 7. 配置 `sudoku.cfg`

**完整取值与注释以 `13-sudoku/sudoku.cfg` 为准**（唯一可信源）。分区职责：

| 分区 | 关键项 | 职责 |
| --- | --- | --- |
| `[board]` | 11 个颜色 + `cell_size` | 场地面、棋盘面、网格两种线宽、给定/玩家/冲突三种数字色、光标与同行列宫两种底色、铅笔记号、自动候选、以及超级作弊的统一绿 |
| `[text]` | `digit_scale` `note_scale` | 大数字与铅笔数字相对格宽的字号比例 |
| `[generator]` | `difficulty_names` `difficulty_blanks` | 三档难度名与各自的空格数目标 |
| `[audio]` | `fill_freq` `erase_freq` `note_freq` `clash_freq` `complete_freqs` `record_freqs` `start_freq` | 各事件的基频与音阶 |
| `[hud]` | `font_size` `margin` | HUD 与底栏 |

- ⚠️ **`SudokuSettings` 每个键都有兜底值**，所以往 cfg 加键却忘了改读取表**不会报错**，只会静默用兜底值。加键时两处一起改。
- 颜色以 6 位 hex 存，加载时 `Color.html` 解析。代码内**零调参魔法数**。

## 8. 只读叠加层（`sudoku_debug.gd`，`class_name SudokuDebug`）

- **`P`（`debug_toggle`）**：画在**棋盘左侧的空白带**里（那块地方本来空着，所以开着也压不到任何格子）。七行读数：该档最佳成绩、难度序号、挖洞目标与实际挖到数、给定格数、空格数、冲突格数与**与答案不符的格数**、光标坐标与其候选数、累计错误次数。
- **它只读**：一个数字都不往盘上写。`WRONG` 那一行虽然查了答案，但它只显示计数，不告诉你哪几格。
- ⚠️ 开关**必须"出去也重绘"**——照抄 `03-pacman/scripts/pacman_debug.gd` 的带 setter 写法（DECISION_LOG 029）。
- 读数用一个调色板里不出现的亮品红 `FF3FA4`，方便用像素计数验证开关。

## 9. 程序化音频（`sudoku_audio.gd`，`class_name SudokuAudio`）

启动时合成 PCM 到 `AudioStreamWAV`（22.05 kHz / 16-bit / 单声道），6 个声部轮转。

| 事件 | 音色 | 触发 |
| --- | --- | --- |
| 填入 | 短音，**音高 = `fill_freq` 上第 n 个半音**（n = 数字） | 一次合法填入 |
| 擦除 | 低音短音 | 真的擦掉了东西 |
| 铅笔 | 更轻更短的音 | 标记确实翻转了 |
| 冲突 | 低音 | 造成或试图改动给定格 |
| 完成 | 上行四音 | 通关 |
| 破纪录 | 上行三音 | 用时进最佳 |
| 开局 | 柔和起音 | 每一局发牌后 |

- ⚠️ `_render` 用**相位积分**而不是 `sin(2π·f(t)·t)`——后者在 f 变化时会**跳音**而不是滑音（11-pinball 踩过）。
- 合成 helper 与 01–12 同源，**后续可整体抽到 `plugins/`**（DECISION_LOG 015 备注，时机由用户定）。

### 10.2 本作的私有语义动作（`sudoku_input.gd`）

| 语义 | 来自 |
| --- | --- |
| `sudoku_up/down/left/right` | `arrow_*` / `wasd_*` |

| `sudoku_erase` | `erase` |

### 10.3 鼠标

**鼠标是键盘的捷径，不是第二条玩法**：左键点格 = 选中；**右键点格 = 选中并切换铅笔模式**。都通过 `SudokuView.cell_clicked(index, pencil)` 发信号，play 收到后走和键盘完全一样的那条路。

## 11. 踩过的两个坑（DECISION_LOG 097）

这两个都让生成器**完全不能用**，且症状（"慢"）与真因（"全是错的"）差得很远，值得单独记。

### 11.1 `ALL_DIGITS` 的位偏移

第一版写的是 `0x1FF`（bit 0..8），而数字是 1..9 用 bit 1..9。于是 **bit 9 永远够不着、digit 9 永远不会被尝试**——**一行最多填八个数字，任何盘都填不满**。

症状是"空盘求 2 个解要 871 ms"（它其实在穷尽整棵搜索树然后返回 0 个解）。修法是 `0x3FE`，代价是 `POPCOUNT` 表从 512 项变 1023 项。

**教训**：位掩码的位号从哪开始，要么让数据跟着掩码走，要么让掩码跟着数据走，**不能两边各按各的直觉来**。

### 11.2 `PackedByteArray` 是写时复制

`full_solution` 第一版把 grid 交给 `_fill()` 就地填，然后返回自己的 `grid`——**返回的永远是空盘**，因为 `PackedByteArray` 是值语义（写时复制），`_fill` 填的是它自己的副本。

改用 `Array[int]`（真引用）作为工作网格后一切正常。**同时 `Array` 也让三个掩码数组天然地跨递归共享**，undo 逻辑写起来和 C 一样直白。

**教训**：**`Array` 和 `Packed*Array` 的传递语义不一样**。"就地填一个缓冲区"这种写法只对前者成立；对后者，要么走返回值，要么换引用类型。而 `Array[int]`（类型化数组）**仍然是 `Array`，是引用**——所以掩码那边一直是对的，只有 grid 那边错。

## 12. 风险 / TODO

| 事项 | 优先级 | 说明 |
| --- | --- | --- |
| 铅笔标记没有"自动清理" | 低 | 填入数字会清掉本格标记，但**别人格的标记不会因为你的填入而失效**——真实的数独 App 会清。不做是有意的（那是一种自动推理），留着等用户拍板。 |
| 无撤销 | 低 | 与 08/09 口径一致；`SudokuBoard.snapshot()` / `restore()` 已经写好，加撤销只是接线。 |
| 三档难度的**分布**未验证 | 中 | 三档只差空格数，都用同一个生成器。**实际难度是否拉开**（HARD 是不是真的需要多一些技巧）只有玩起来才知道。见 §14。 |
| `SudokuCell` 每帧全量重绘 | 低 | 一次输入重画 81 个格子。实测无感；真成为瓶颈时再按脏格重绘。 |

## 13. 验收

### 可自动校验的（headless）

```bash
godot --headless --path . --import
godot --headless --path . --script res://13-sudoku/scripts/sudoku_check.gd
godot --headless --path . res://13-sudoku/sudoku.tscn --quit-after 120
```

- 断言套件（`sudoku_check.gd`，**199 项**）：
  - **求解器**：Project Euler #96 第一题唯一解；合法终盘计 1；空盘计 >1；挖一格仍唯一；重复数字 → 0 解；**已知解本身是合法的**。
  - **棋盘**：给定格的三种拒绝（覆盖 / 擦除 / 铅笔）；`place` / `erase` / `toggle_note` 的往返；候选数确实排除同行、列、宫；候选计数与掩码一致；冲突只标涉及的格、不误伤其余；`is_complete` 的三种情形；`snapshot` / `restore`。
  - **生成器**：**30 局（三档各 10 局）逐局回验"解唯一"**；终盘合法；挖洞数不超过目标、且确实挖掉了那么多；给定格全部与解一致。
  - **配置**：三档数量、空格数递增、棋盘尺寸、字号下限、超级作弊色是全库统一的绿。
- **冒烟（一次性脚本，已跑完删除）**：实例化真实 `play.tscn` 并驱动——发牌、给定格拒绝、冲突计数与标红、擦除、铅笔往返、光标边界、`[` 与 `]` 的行为与标记的持久性、答满全盘触发 `solved`。**27 项全过。**
- **场景加载**：`--quit-after 120` 无脚本错误。

### 已跑过的（实测数字）

- `--import`：**零 error / warning**，15 个 `Sudoku*` 全局类全部注册。
- 断言 199 项通过 / 0 失败；冒烟 27 项通过 / 0 失败。
- 生成速度：`full_solution` **1 ms**；三档单局 **3.2 / 5.3 / 8.7 ms**，**三档均挖满目标**（40 / 48 / 52 个空格，10 局平均等于目标）。
- 唯一性：30 局全部回验为唯一解。

### 只有人能定的

- 观感：配色与两种线宽、光标与同行列宫的底色深浅、格子尺寸（`cell_size`）、字号比例。
- 手感：`Z` 切铅笔是否顺手、右键点格切铅笔是否符合直觉、`[` 的自动候选是不是太刺眼。
- 听感：填入音随数字上行的辨识度、冲突音是否够"不对"。
- 难度：三档是不是真的拉开（§12 那条）。
