## 3. 结构模型（场景即架构，CONSTITUTION 五点五）

```
pipes.tscn  (Pipes, Node, pipes_root.gd)
├─ ScreenHolder (Node)                     三屏整屏替换
├─ Audio (Node, pipes_audio.gd)
├─ Save (Node, pipes_save.gd)
└─ InputTranslator (Node, pipes_input.gd)  语义动作注册，跨屏只注册一次
```

**对局屏有两个，不是四个**：

```
scenes/play.tscn      (Play, PipesPlay)      LINK
scenes/play_net.tscn  (PlayNet, PipesNetPlay) TURN / SHIFT / SLIDE
```

分开的依据是**棋盘的种类**，不是模式的个数。LINK 的棋盘是"每格属于哪条颜色"，另外三个的棋盘是"每格一个管件"。三个管道模式共用同一个棋盘类型、同一套胜负判定，只有**动词**不同，所以它们共用一块屏。

```
play_net.tscn  (PlayNet, Control)
├─ Backdrop (ColorRect)
├─ Board (Control, pipes_net_view.gd)
├─ Hud (Control, pipes_hud.gd)
├─ Overlay (Control, pipes_debug.gd)      P 叠加层，默认关
└─ PauseHolder (Node)
```

### 3.1 ★ 两种棋盘都没有逐格节点，`_draw` 一次画完

LINK 的格子是"一块底色 + 几段线 + 可能一个圆点"，管道模式的格子是"中心一个方块 + 朝各开口的几段线"——两者都**没有逐格状态需要节点承载**，所以各自一个 `_draw` 画完整盘。

13-sudoku 是反例：那里每格要在大数字和 3×3 铅笔数字之间切换，**是两种形态**，才需要 81 个节点。

两个 view 都只管两件事：**画**，和**回答"鼠标在哪一格"**。规则一律由 play 转达给模型。

## 4. 数据模型

### 4.1 LINK（`pipes_level.gd`，`class_name PipesLevel`）

**纯逻辑，`extends RefCounted`**——不碰场景树、不发信号。

- **占用是每格一个位掩码（`PackedInt64Array`），不是"属于哪条颜色"的编号**。原因只有一个：`]` 允许线压线，而**交叉格同时属于两条颜色**，一个编号说不出来。
- `drawn[c]` 是玩家画的格子序列（可能为空、可能只有一格）；`ends[c]` 是生成时定下的两个端点。
- **一条颜色"通"了 = 它画的链从自己的一个端点到另一个端点**（顺序任意、路线任意）。
- **过关 = 所有颜色都通 且 每格 `occupancy != 0`**。判据**从不比对 `solution`**——另一条合法走法也是解。
- `covers()` / `color_at()` / `colors_at()` / `is_crossing()`；交叉格 `color_at` 返回 -1。

**绘制规则**（`begin_stroke` / `extend_stroke` / `end_stroke`）：
- **起笔必须是端点**，且会**先清掉这条颜色已有的线**。
- 延伸必须**与当前末端相邻**；目标格是自己另一端 → 允许；是自己已覆盖的格 → 走截断分支；是别人的地盘 → 只有 `]` 开着才允许，**且任何圆点都不许压**。
- **拖回自己走过的格子 = 截断**，并释放截掉那几格的占用位。
- **松手保留半成品**。

### 4.2 管道模式（`pipes_net.gd`，`class_name PipesNet`）

**一个类服务三个模式。** 格子内容是一个 **4 位掩码**（北 1 / 东 2 / 南 4 / 西 8），表示这根管子朝哪几边开口：一口是端点，两口是直管或弯管，三口是丁字，四口是十字。

三个模式**只在两个地方分支**：
1. **玩家怎么动它**——`turn()` / `shift_line()` / `slide_step()`；
2. **打乱时怎么动它**——生成器挑哪个动词。

棋盘本身、"通了"的含义、判定的写法，三者完全一致。

- **`is_joined()`：每个开口都必须有另一个开口正对着它，且没有任何开口朝着棋盘外。** 空格不参与（它是缺口，不是断头）。
- `OPPOSITE` 表给出每个方向对面的那一位；`neighbour()` 负责越界。
- **`shift_line(index, horizontal, amount)` 是循环的**——挪出头的从另一头绕回来。这不是风格选择，是**可逆性的来源**：绕回意味着没有任何东西掉出棋盘，同一个位移的反方向就能还原。
- **`slide_step(cell, direction)` 只走一格**。生成器**只用这一格版本**打乱，理由同样是可逆：滑完空格就在这根管子原来的位置，反向滑一下即可还原。`slide_far()` 是留给玩家的"一次滑到底"，不参与打乱。
- `pinned` 是给"不许动的格子"留的口子（本作四个模式都没有用到，先留着不加乱用）。

## 5. 生成器

两款生成器都遵守同一条原则：**先造一个合法的解，再用可逆的操作打乱**。所以四个模式**都不需要求解器**——有解是构造出来的。

### 5.1 LINK（`pipes_generator.gd`）

网格被切成若干条**刚好铺满**的路径，每条的两端就是一对同色点。写了三版才成：

1. **贪心游走 + 留空检查**：**0/20 成功**——判据太紧，游走被反复截断，5×5 都出不来。
2. **随机哈密顿路径 + 切段**：一定合法，但**慢到跑不完**（5×5 就 304 ms，7×7 卡死）。
3. **合并生长（采用）**：**每格先各是一条长度 1 的路径**，反复把**端点相接**的两条焊起来，焊到剩 `pairs` 条。
   - **覆盖全格是起始状态而不是要达到的目标——所以没有可失败的地方。** 这是它成立的根本原因。
   - 焊接要**防环**（接上后两端相接就成了环，而环没有端点）。
   - 被吞掉的那条在 `paths` 里置 `null` 而**不删元素**（否则索引全乱）。

**形状也是调出来的**：总合并最短 → 五色分布均匀但**每盘都是竖条纹**；总随机 → 形状自然但 **1/4 的 5×5 留一个 2 格碎头**。采用"**平时随机、短于阈值时才让它插队**"；焊接时两端与其邻居都打乱顺序——固定顺序本身就是条纹的来源。

**性能**：5×5 / 7×7 / 9×9 各 **0.6 / 1.8 / 3.5 ms**，30/30 全部出盘。

### 5.2 管道模式（`pipes_net_generator.gd`）

两步：

1. **在网格上随机长一棵生成树**（随机 DFS）。树边就是管子：每条边给两端各加一个朝向对方的开口。
   - **树天然就是接通的**——每条边都是两个开口正对着，而树没有断头：每个分支都终止在一片叶子上，叶子是一口的管子，那一个口朝着它自己的那条边。
   - 空格**就是走不到的格子**，天然不会变成断头。
2. **用玩家自己的动词打乱**（`Shuffle.TURN` / `SHIFT` / `SLIDE`）。
   - 转四次等于没转；整行挪会绕回；滑动留下的空位就在原处。**每一步都反向可做，所以反向做一遍就是解法。**

**两个必须处理的坑**：

- **空格不能把网格切成两块。** 生成树只覆盖起点所在的那一块，剩下的一块会留成空洞——在滑动盘上更糟，被空格围死的管子**永远挪不动**。所以打完树要数一遍覆盖数，不等于"总格数 − 空格数"就重选空格。
- **打乱完必须确认盘面确实不接通。** 极少见，但真会碰上；碰上了就是一开局已经赢了。重试即可。

**性能**：三种打乱各 8 局在 6×6 上 **1.5 / 0.6 / 1.8 ms**，24/24 全部出盘。

## 6. 对局

### 6.1 LINK（`pipes_play.gd`）

- **鼠标**：`PipesBoardView._input` 报告 `cell_pressed` / `cell_dragged` / `cell_released`，play 转成 `begin_stroke` / `extend_stroke` / `end_stroke`。
  - **走 `_input` 而不是 `_gui_input`**：拖拽大部分时间在棋盘外面，`_gui_input` 在离开控件后就不再给了；而"在边缘外松手"也必须能结束这一笔。
  - **格子变了才发 `cell_dragged`**，否则同一次移动会按像素重复触发。
- **通关后延迟 0.7 秒**再发 `solved`：解好的盘值得看一眼。
- **`[`**：画出下一条还没连好的颜色的完整答案（青色），每按一次换一条。
- **`]`**：允许线压线（交叉处压白片），**但圆点仍然穿不过去**。

### 6.2 管道模式（`pipes_net_play.gd`）

同一块屏服务三个模式，**分支只有两处**：

- **按下**：`TURN` 转一格（左键顺时针、右键逆时针）；`SHIFT` / `SLIDE` 记下"手里拿着的是哪一根"。
- **拖到相邻格**：`SHIFT` 让整列朝那个方向挪**一格**；`SLIDE` 把那根管子朝方向**滑一格**。

其余全部共用：计时、撤销、提示、作弊、暂停、结算。

- **`SHIFT` 是竖直的，而且方向跟手**：手往上还是往下，整列的内容就往那边走。反向的约定读起来像棋盘在跟你较劲。
  - **横向被砍掉了**（`DECISION_LOG 101.4`）：行也能挪的时候，每一次横向移动都会毁掉三行以外的成果，这一款因此成了四个模式里最难的一个。只剩竖直之后，一列内的管子序列在滑动前后不变——"滑动的基本单位是块，块内管道是确定的"。
- **`SLIDE` 追的是管子不是指针**：`_held_cell` 记的是那根管子的当前位置，它一撞上东西就落后于指针，此后指针换格仍按新方向试。
- **过关判定加了一道 `piece_count() == 0` 的防线**：空盘在 `is_joined()` 眼里是"接通"的（没有开口就没有断头），所以必须先确认盘上确实有东西。
- **`[`**：在底色上淡淡画出答案里每根管子的朝向（`_answer` 与当前盘面共用同一段绘制代码，所以两者画法不会漂移）。
- **`]`**：**把整盘换成答案**。拆掉的是这三个模式赖以存在的约束——"进度只能一次一格"。
- **撤销**：在**按下时**推一步快照，所以一次拖动（可能挪好几格）是一个撤销单位。

## 7. 配置 `pipes.cfg`

**完整取值与注释以 `14-pipes/pipes.cfg` 为准**（唯一可信源）。分区职责：

| 分区 | 关键项 | 职责 |
| --- | --- | --- |
| `[board]` | 底色 / 空格 / 网格 / 光标 / 桥接片 / 提示 / 超级作弊 / 三种文本色、`cell_size`、`line_width`、`dot_scale`、`joined_dot_scale` | LINK 棋盘的一切外观 |
| `[colors]` | `palette` | LINK 的颜色，按生成器编号取用 |
| `[levels]` | `sides` / `pairs` / `min_run` | LINK 每关的边长与颜色数；`min_run` 是生成器允许留下的最短一条 |
| `[net]` | `pipe_color` / `joined_pipe_color` / `pinned_pipe_color` / `pipe_width` / `hover_alpha` | 管道棋盘的外观。接头的圆的直径**就是** `pipe_width`（取一半作半径），所以拐角是弯不是鼓包——它不是一个能单独调的旋钮 |
| `[net_levels]` | `shuffle_steps` / `slide_gaps` | 三个管道模式共用的难度表：打乱步数、滑动盘的空格数 |
| `[audio]` | 四个基频 + 两组音阶 | 各事件的音高 |
| `[hud]` | `font_size` `margin` | HUD 与底部那行 |

- ⚠️ **`PipesSettings` 每个键都有兜底值**，所以往 cfg 加键却忘了改读取表**不会报错**，只会静默用兜底值。加键时两处一起改。
- **`sides` 与 `pairs` 必须等长**（`level_count()` 取较小值，越界时返回末项）；`shuffle_steps` / `slide_gaps` 越界时返回末项。

## 8. 只读叠加层（`pipes_debug.gd`，`class_name PipesDebug`）

- **`P`（`debug_toggle`）**：画在**棋盘左侧的空白带**里，八行左右：模式与关卡、边长 / 管件数 / 空格数、**还没接上的开口数**、是否已接通、撤销栈深度、提示开关、鼠标所在格及其管件掩码、本关最佳。
- **它只读**：一个格子都不改。
- ⚠️ 开关**必须"出去也重绘"**——照抄 `03-pacman/scripts/pacman_debug.gd` 的带 setter 写法（DECISION_LOG 029）。
- 读数用调色板里不出现的亮品红 `FF3FA4`，方便用像素计数验证开关。

## 9. 程序化音频（`pipes_audio.gd`，`class_name PipesAudio`）

启动时合成 PCM 到 `AudioStreamWAV`（22.05 kHz / 16-bit / 单声道），8 个声部轮转。

| 事件 | 音色 | 触发 |
| --- | --- | --- |
| 走一步 | 短音，**音高按步数上行**（12 级封顶） | LINK 拖出一格、管道模式转/挪/滑一次 |
| 接通 / 应用答案 | 上行两音 | LINK 连通一条、`]` 应用答案 |
| 撤销 | 下行滑音 | `Z`，以及 LINK 的清除 |
| 按了没用 | 低音 | 操作不成立 |
| 过关 | 上行四音 | 判定通过 |
| 破纪录 | 上行三音 | 用时进最佳 |
| 开局 | 柔和起音 | 每一关发牌后 |

- ⚠️ `_render` 用**相位积分**而不是 `sin(2π·f(t)·t)`——后者在 f 变化时会**跳音**而不是滑音（11-pinball 踩过）。
- 合成 helper 与 01–13 同源，**后续可整体抽到 `plugins/`**（DECISION_LOG 015 备注，时机由用户定）。

## 11. 这一款踩过的三类坑

### 11.1 "跑得慢"和"全错"在外观上没有区别（DECISION_LOG 099）

两次真正的诊断起点都是**荒谬的数字**——一次是"空盘求解要 871 ms"（应当 1 ms 以内），一次是"一个 5×5 棋盘 304 ms"。两次按性能查都白查：真因是 `ALL_DIGITS` 的位偏移（**同一个 bug 在两天里犯了两遍**）和 `Array.reversed()` 不存在导致的编译失败。

⚠️ **`godot --headless --script` 下的编译错误不退出进程**——`quit()` 永远到不了，从外面看就是"跑了三分钟没结果"。看到"超时"先去翻输出里有没有 `SCRIPT ERROR`。

### 11.2 容器的类型标注决定行为，不只是决定能不能编译（DECISION_LOG 101.1）

同一大类里连栽三次，每次都是不同变种：

| 容器 | 坑 |
| --- | --- |
| `PackedByteArray` | **写时复制**：函数里就地填的是自己的副本（097.2） |
| `Array` | **没有 `reversed()`**，只有就地 `reverse()`；`resize` 补出来的是 **`null`** |
| `Array[int]` | `resize` 补出来的是 **`0`**，而且是**引用**，跨函数共享 |

最后一条最阴：`Array` 和 `Array[int]` 看起来只差一个类型标注，**默认填充值就不一样**。`resize` 之后 `int(null)` 直接抛异常，一局游戏崩在第一次通关上——而我在那行上面写的注释还断言"数组会补 0"，**注释是错的，代码照着错的注释写**。

### 11.3 "谁先谁后"是布局类 bug 的第一嫌疑（DECISION_LOG 101.2）

`_layout()` 向 view 要棋盘尺寸，而那个尺寸是 `refresh()` 在**更晚**的时候喂进去的——于是 `_layout()` 拿到 `Vector2.ZERO`，把棋盘的左上角放到了 `FIELD * 0.5`，也就是窗口正中。**不报错、不警告，只是安静地给出零。**

## 12. 风险 / TODO

| 事项 | 优先级 | 说明 |
| --- | --- | --- |
| `shuffle_steps` 只是步数，不是难度 | 中 | 打乱 40 步的盘不一定比 20 步的难——**步数只是"离解多远"的一个粗糙代理**。真实难度只有玩起来才知道，见 §13。 |
| LINK 偶尔切出"块状"分区 | 低 | 合并算法偶尔切出比较规整的块（一条直线、一个方块），一眼可解。够用，但不够耐玩。 |
| 管道模式没有"最短步数"概念 | 低 | 玩家挪一大堆废步也算过关。真在意就得加计步器与星级，那是另一件事。 |
| 无自动存档"当前盘面" | 低 | 退出即丢当前这一局（只存通关记录）。与 10–13 口径一致。 |
| `check` 里的时间阈值写死 | 低 | 机器负载会让它偶发失败。它是"数量级护栏"不是性能断言。 |
| `pinned` 字段没用上 | 低 | 四个模式都不需要钉死的格子。留着是给"以后想加"的口子，删了也行。 |

## 13. 验收

### 可自动校验的（headless）

```bash
godot --headless --path . --import
godot --headless --path . --script res://14-pipes/scripts/pipes_check.gd
godot --headless --path . res://14-pipes/pipes.tscn --quit-after 120
```

- 断言套件（`pipes_check.gd`，**234 项**）：
