## 3. 结构模型（场景即架构，CONSTITUTION 五点五）

### 3.1 入口与切屏

`pinball.tscn` 的根是 `Node`（`pinball_root.gd`），管三屏：**主菜单 / 台面 / 结算**。切屏是**整屏替换**，与 `10-marble-race` 同构。

```
PinballRoot (Node)              pinball_root.gd —— 局：球数 / 分数 / 切屏
├─ ScreenHolder (Node)          ← 主菜单或台面，同时只留一个
├─ OverlayLayer (CanvasLayer)   ← HUD 与暂停菜单常驻，浮在所有屏之上
├─ Audio (Node)                 pinball_audio.gd
└─ SaveStore (Node)             save_store.gd（常驻，跨屏）
```

### 3.2 台面场景 `scenes/table.tscn`

**静态骨架写进场景**，动态内容由 `table_builder.gd` 填进预留挂点。

```
Table (Node3D)                          ← 台面坐标架，绕 X 轴倾斜 TABLE_TILT
├─ Floor      (StaticBody3D)            ← 地板：薄 BoxShape3D
├─ Walls      (StaticBody3D)            ← 空壳，builder 往里填逐段 BoxShape3D
│   └─ WallMesh (MeshInstance3D)        ← 墙体可视网格，builder 填入
├─ Bumpers    (Node3D)                  ← 挂点：bumper.tscn 实例
├─ Slingshots (Node3D)                  ← 挂点：slingshot.tscn 实例
├─ Flippers   (Node3D)                  ← 挂点：FlipperLeft / FlipperRight
├─ Ball       (RigidBody3D)             ← ball.gd，只有一个
├─ DrainLine  (Node3D)                  ← 只读标记（判定是算出来的，不是碰撞体）
├─ Camera     (Camera3D)
└─ DebugLayer (Node3D)                  ← pinball_debug.gd，P 叠加层
```

**台面坐标架**：`Table` 本地坐标里，**X 横向（左负右正）、Z 纵向（远端 −Z 是台面高处，近端 +Z 是玩家这边）、Y 是台面法线**。倾斜由 `Table.rotation.x = deg_to_rad(TABLE_TILT)` 一次设定，**所有布局数据都用这个坐标系写**，不受倾斜影响。

## 4. 物理模型（本作的成败点）

### 4.1 分工——谁归 Jolt，谁归手写

| 归 **Jolt** | 归 **手写** |
| --- | --- |
| 地板、四周墙体、发射道内壁 | **flipper 与球的一切相互作用** |
| 保险杠、弹弓的碰撞与反弹 | 球速上限 |
| 球自身的积分与重力 | 掉球判定 |
| 球与静态体的接触识别 | 三个全局作弊键 |

**⚠️ flipper 在 Jolt 的世界里不存在。** 它**没有 `CollisionShape3D`**，球与它永不发生引擎层面的碰撞。理由是混合方案最容易烂在这里：若 flipper 既有碰撞体又吃手写冲量，球会同时拿到"引擎的软推"和"我的冲量"两股力，比例还随帧变化——**弹飞的时候分不清是谁干的**。干净的分界线是：**球撞到的静态几何全归 Jolt，球撞到的 flipper 全归手写**。

flipper 只有：一个旋转的 `Node3D`（承载可视网格）+ 脚本里的一条胶囊轴线段。

### 4.2 球的节点配置

```gdscript
ball.mass = BALL_MASS                # 初值 1.0
ball.gravity_scale = 1.0
ball.continuous_cd = true            # 高速段不穿墙（10 已验证 51 m/s 撞 0.1 m 墙不穿）
ball.can_sleep = false               # ⚠️ 睡眠刚体收不到 _integrate_forces（10 的教训 3）
ball.contact_monitor = true
ball.max_contacts_reported = 8
```

**`PhysicsMaterial` 只给球设一份**，静态体留默认。Godot 的接触摩擦取两方的**乘积**，台面默认的 1.0 乘上球这一份就是最终值——一处设置即可，不必两边同步。

- `friction` 初值 **0.10**
- `bounce` 初值 **0.35**（撞墙要弹，但不能弹成永动）

**球是滚的，不是滑的**（2026-10-12 实机改口）。立项写的是"以滑动为主"，理由是"真机就是滑动"。**实机一看就否了**：`angular_damp = 4.0` 的球像一枚冰球在台面上滑，完全没有弹珠的样子。真机上球其实是**滚**的，而且**自转本身就是玩家读速度的线索**。

改法：**把自转放开**——`angular_damp` 4.0 → **0.05**，摩擦 0.06 → **0.45**（够大才不会一滚就打滑），再加 `linear_damp = 0.15` 当滚动阻力，免得球在斜坡上无限加速。

⚠️ **决定"滚还是滑"的是 `angular_damp`，不是摩擦**——这一条立项时想反了。摩擦只决定滚起来的球**打不打滑**；球**会不会滚起来**，取决于自转有没有被阻尼当场掐掉。

**球的视觉**：`SphereMesh` + 代码生成的棋盘格纹样（`ImageTexture`，最近邻过滤）。纯色球转与不转在画面上完全一样，**纹样是玩家唯一能读出"球在滚还是滑"的窗口**。

### 4.3 flipper：手写冲量与接触检测

这是本作**唯一的技术难点**，也是"混合"这个词的全部含义。

**几何**：flipper 是绕**支点 `pivot`** 旋转的一段胶囊——轴线段从 `pivot` 到 `pivot + dir(angle) * LENGTH`，半径 `RADIUS`（半厚）。

```
        rest_angle                              up_angle
   左：指向右下 (≈ +22°)                    指向右上 (≈ −28°)
   右：指向左下 (≈ +158°)                   指向左上 (≈ +208°)
```

角度在**台面 XZ 平面**内，按 `atan2(z, x)` 计。**支点在外侧、自由端朝中间**（真机的姿势），两个 flipper 之间留出 drain 缺口。

**① 推进角度**。每物理帧，`current_angle` 以**常数角速度**朝目标角靠近：

```
target = up_angle if 键按住 else rest_angle
step = flip_angular_speed * dt   (抬起)  /  return_angular_speed * dt   (落下)
current_angle = move_toward(current_angle, target, step)
```

用常数角速度（而不是弹簧），有两个好处：**可标定**，且**出射速度与击球点到支点的距离成正比**——这正是真机的特性，"用尖端打飞得更远"，也是"准点打"这个技巧的来源。

**② 接触检测——逐帧距离就够，扫掠是备选**。

立项时说"球半径厘米级、一帧走 25 cm，逐帧测必然漏"。动手当天把数算清楚，**这个判断是错的**：决定漏不漏的是**检测半径**，不是球半径。检测半径是 `BALL_RADIUS + FLIPPER_RADIUS = 0.80`，而球在**速度上限 32** 下每物理帧也只走 **0.53**。要一帧跨过整个检测圈，位移得超过 `2 × 0.80 = 1.6`，对应球速约 **96 m/s**——上限的三倍。

（错在把**球半径**当成了**检测半径**，忘了检测半径里还有 flipper 的那一半。）

所以实现就是每帧一次"球心到胶囊轴段的最近距离"：

```
closest  = 球心在胶囊轴段上的最近点
distance = |球心 − closest|，投影到台面平面内
接触 ⟺ distance ≤ (BALL_RADIUS + FLIPPER_RADIUS) × contact_slack
```

`contact_slack`（初值 1.15）把判定圈略微放大，收掉"擦着边界掠过"这类边缘情形。**代价只是偶尔多报一次接触，而多报不会多给力**——见 ③，力只在两者相互接近时才落。

⚠️ **`_axis_prev` 仍然每帧保留**，但 Phase 0 不拿它判接触，只给 `P` 叠加层画**扫掠带**（两帧姿态并排，一眼看出 flipper 这一帧扫过哪里）。真在实测里发现漏接触，再改成"球位移线段 vs 两帧胶囊"的完整扫掠——门槛值留在 `flipper.gd` 的注释里。

**③ 冲量**。接触点取 `axis` 上离球心最近的那一点，法线 `n` 从接触点指向球心（投影到台面平面内）：

```
v_surf = ω_vec × (contact − pivot)      ω_vec = (0, ±ω, 0)，ω = 当前角速度
v_rel  = v_ball − v_surf
vn     = v_rel · n
若 vn < 0:                              # 在靠近
    j = −(1 + FLIPPER_RESTITUTION) * vn
    v_ball += j * n                     # flipper 视为无限质量
```

**④ 位置修正**：把球沿 `n` 推到"恰好相距 `BALL_RADIUS + FLIPPER_RADIUS`"的位置，不留穿透。

**⑤ 顺序**：`ball.gd` 的 `_integrate_forces` 里，先读 flipper 的当前角度，再做检测与施加。flipper 自身的角度推进放在它自己的 `_physics_process` 里——**同一个物理帧内，角度推进必须发生在球的积分之前**，所以 flipper 的 `process_physics_priority` 要高于球（数值更小）。

### 4.4 球速上限与发射

**上限 `max_speed`（初值 32）**：在 `_integrate_forces` 末尾对 `linear_velocity` 整体 clamp。发射道那一段是全程最快的地方，也是最容易穿墙的地方——**上限与 CCD 两道保险都要有**。

**发射（plunger）**：球停在发射道底部。按住 `fire` → `charge` 从 0 线性涨到 1（`CHARGE_TIME` 初值 1.1 s）并**循环**（蓄满不松就停在满值）。松开 → 沿发射道方向（−Z）给初速度：

```
v = lerp(LAUNCH_MIN_SPEED, LAUNCH_MAX_SPEED, charge)      # 初值 10.0 → 42.0
```

球沿窄道上行，被**顶弧**导向左进入台面。发射道的内壁是 Jolt 的静态体，球在该段的**出轨**是最需要盯的失败模式。

### 4.5 掉球判定（不用 Area3D）

**用位置判定，不用碰撞体**：每物理帧检查球心，若 `ball.z > DRAIN_LINE_Z`（初值 10.5）且 `|ball.x| < DRAIN_HALF_WIDTH` → 掉球。

理由：`Area3D` 在极端速度下可能**漏检**（球一帧跨过整个触发区），而位置判定不可能漏——**掉球漏掉一次就是玩家白丢一条命**。

**兜底**：球心 `y < −8`（台面本地）或离台面中心水平距离 > 40，一律判掉球。这是防"物理出 bug 把球弹到天涯海角"的安全网，正常流程永不触发。

**掉球是一次性的（`_lost` 闩锁），而且要立刻把球冻住**。不闩锁的话球下落的每一帧都会报一次掉球；不冻住的话它会一直落满整局，位置也再没有任何意义——上面已经被告知了，没有人需要它继续动。复位时清闩锁、解冻。

**蓄力不足的球会滚回车道并重新待发**。它没越过顶弧，沿车道滑回底部停下。此时发射器自动重新生效——**只有发射道在 `LANE_INNER_X` 右边**，所以一个 `x` 坐标加"速度接近零"就足以认定它在家，不需要额外状态。

## 5. 台面几何（复刻 Space Cadet）

### 5.1 数据来源

**台面的每一个数字都来自原版 `PINBALL.DAT`**（见策划案的「参考」一节）。`table_layout.gd` 是这些数据的唯一落点：

- `wall_polylines()` —— 原版的 **54 段墙**。原版有 64 个墙对象，其中 10 个是圆或单点，**本作暂不支持圆形墙，已跳过**；剩下的逐段照抄，一个点没动。
- `flipper_mounts()` —— 2 个 flipper 的**支点、长度、两个极限角**。原版存的是"支点 + 摆动两端的**尖端位置**"，角度是从那两组坐标现算的，所以不是整数：**34.96° / −34.67°，行程 69.6°**（比原来手定的 50° 宽得多）。
- `bumper_spots()` —— **7 个保险杠**，每个带自己的半径（上三个 r=0.35、右下三个 r=0.25、右上还有一个 r=0.35）。**不再是 `BUMPER_RADIUS` 一个常量**，半径跟着位置走。
- `BALL_RADIUS = 0.3`、`DRAIN_Z = 14.437`、`LANE_INNER_X = 6.5`（发射道内壁，原版组 `g293`）。
- `ball_spawn()`、`plunger_spot()`。

⚠️ **x 在录入时取反**：原版的 x 正方向朝**左**，本作朝右。不取反的话整张台面会左右镜像——而镜像的弹珠台，`A` 键会去动右边的挡板。

### 5.2 台面尺寸

**16 × 27.88**（x ∈ [−8, 8]，z ∈ [−14, 13.88]）。**原版坐标直接沿用、不缩放**——它和立项时随手定的 14 × 28 几乎一样大。纯属巧合，但省掉了整套比例换算。

### 5.3 还没搬进来的

原版有 **40 多个几何机关**，现在只搬了**墙 + 7 个保险杠 + 2 个 flipper**。其余按 §12 的分批补：靶 22、洞 4、单向门 9、滚过 17、门 2、trip 5、旗帜 2、kicker 2 + kickout 3、坡道 2。

⚠️ **原版的「回弹」（rebound，就是别家说的 slingshot）不是独立对象**——它藏在墙段里（`v_rebo1..4`）。所以现在那 4 个回弹**只是普通墙**：球撞上会被弹开，但**不会主动踢**。要那个行为，得先把对应的墙段认出来。

⚠️ **同理，圆的墙（10 个）被跳过了**，台面上会少几处圆形碰撞体。这 10 个里有几个是"点碰撞"（只有一个坐标），本来就是退化数据。

### 5.4 ⚠️ 两条容易踩的坑

1. **折线的端点位置就是缺口的位置**：逐段 Box 是双向的，所以绕向本身不再是"会不会穿墙"的问题。**但 drain 缺口与车道开口两侧那两个端点决定了缺口有多宽**——写错一点，球就会从一个不该存在的地方漏下去，而画面上看不出任何异常。**用探针验证：球贴着轮廓内侧跑一圈，全程不出界**。
2. **墙的粗细与高度是两个方向的错**：
   - **⚠️ 原版的墙有两种形态，而且都不是"粗板子"**：左右外墙（`g286/g287`）是**闭合矩形**，本身已经 **0.25 厚**；而顶部弧（`g280`）是**开放折线**，也就是**零宽度的中心线**。`wall_thickness` 会**加在两者之上**，所以它必须很小——否则那几段**本来不需要加粗的矩形**会变成两倍厚。
   - **粗到 0.6 时**（= 球的一整个直径）：相邻墙段互相侵入，台面看着像一堆叠在一起的板子；而且对中心线型的墙，居中加粗会让墙**整体偏移半个厚度 = 一整个球半径**，那正是"错位"。现在是 **0.1**（球半径的 1/3）：几乎看不见，碰撞盒在拐角处又还能碰上。
   - **高度必须够**：`wall_height` 2.5（约 4 个球径）。发射道那段球速最高，墙太矮球会**骑上墙顶飞出去**，而这个失败模式**只在高速下出现，低速自测发现不了**。

## 6. 相机

- **固定机位**，挂在 `Table` 下（因此跟着倾斜），位于台面正上方偏近端，朝台面里看：

```
position = Vector3(0, 24, 14)
look_at  → Vector3(0, 0, −2)      # 台面本地坐标
fov      = 52   (透视)
```

- 机位**固定不动**——弹球的画面稳定比跟随重要，球的运动已经在整个画面里读得出来。
- 倾斜角 `TABLE_TILT`（初值 **8.0°**）比真机的 6.5° 略陡一点：真机球速偏慢，游戏里需要更明显的"往下滑"。

## 7. 计分与球数

- **得分**：保险杠 **100** / 弹弓 **50**。撞一次加一次，**不做倍率、不做连锁任务**（首版）。
- **同一次接触只计一次分**：`contact_monitor` 报的是"当前帧的接触对"，持续贴着会每帧都报。记上一帧的接触对象集合，**只在"新出现"时计分**。
- **识别撞到谁**：拿 `state.get_contact_collider_object(i)` 的返回值做 `is PinballKicker` 判断。⚠️ **球不需要区分保险杠和弹弓**——每个 kicker 自己带着分值和音高，球只管把"撞到了、值多少、什么调"报上去。这比立项时写的"用命名节点引用逐个比对"更好：**再加第四种机关，球一行都不用改**。
- **能量从哪来（kicker 的抛出）**：Jolt 负责"球不会穿过去"（真碰撞体），**抛出量由 `kicker.gd` 加**——被动弹性永远不可能还给球比它带来的更多的能量，而真机的保险杠是**电磁线圈驱动的**。与 flipper 同一条口径：**引擎管不穿透，我管力**。
- **球数**：开局 **3**。掉一球 −1，球回到发射道；剩 0 条 → 结算。
- **连击的听感**：连续撞保险杠时音高逐次上爬（封顶），**不改变数值**——只做反馈，不做机制。

## 8. 存档

- 文件 `user://pinball.save`，内容 `best_score` + `version`。
- **三种坏情况都要回退到空存档并在界面上明说**（"存档无法读取"），而不是把空白成绩当成对的：文件不存在、解析失败、`version` 不符。
- ⚠️ **这是全库第二处持久化**（第一处是 `10-marble-race`）。两份实现稳定之后，**是否抽成 `plugins/` 由用户判断**（CONSTITUTION 二）；本作先各自实现、**不复制 10 的代码**。
- 实现是 `ConfigFile` 加一个 `version` 字段，外加一个 `loaded` 标志对外说明"现在看到的是不是真的"。**菜单上写明 `BEST -- (SAVE UNREADABLE)`**，而不是把一个 0 当成真有人打过的最高分。

⚠️ **`pinball_settings.gd` 的读取表是逐条手写的——加 cfg 键却忘改读取表不会报错，只会静默用兜底值**（`10` 栽过一次）。加键时两边一起改。

⚠️ **`length` 与 `flip_angular_speed` 相对立项时都改了，理由值得记住**：立项写的是 `length = 3.2` / `flip_angular_speed = 16`，算出来尖端线速度 51 单位/s。可本作是**慢速弹球**——台面宽 14 单位约等于真机的 510 mm，真机球速 5 m/s 换算过来是 182 单位/s，一帧走 3 个单位，根本没法看。既然整个时间尺度慢了约 7 倍，flipper 也该跟着慢下来，否则它相对球速就是**快 7 倍**，一碰就飞。

⚠️ **本作的时间尺度改过两次，现在这版是「接近真机」，不再是立项时的「慢速」**：

- 立项按「慢 7 倍」设计，理由是**真机球速换算过来一帧走 3 个台面宽，根本没法看**，`flip_angular_speed` 一度压到 8。
- 实机两轮反馈都是「太慢」，最后把球本身提上去：**`gravity_scale = 2.0` + `linear_damp = 0` + `max_speed = 64`**，并让**所有施加力的量同比例跟上**（`flip_angular_speed` 14、`bumper_kick` 13、`launch_max_speed` 42…）。**球快一倍就必须让挡板也快一倍，否则它相对球速慢了一半，读起来像纸糊的。**

⚠️ **`max_speed = 64` 是这套架构的实用上限**：球每物理帧走 **1.07** 单位，而 flipper 的判定半径是 **1.60**——**再往上（约 90 单位/s）球就会一步跨过挡板而不被检出**（§4.3）。要更快只能改架构：**把整个台面的尺度缩小**，让同样的速度对应更短的路程。

⚠️ **摩擦不是速度的杠杆**：纯滚动的球接触点不滑移，**摩擦不做功**——降摩擦一点也不会让球更快，只会让它更容易打滑。它还有个硬底：16° 下纯滚动要求 `μ ≥ (2/7)·tan(16°) = 0.082`。**真正偷速度的是 `linear_damp`**，而「加速慢」要怪沿台面的重力分量。

⚠️ **`tilt_deg` 与 `friction` 是实机调过的**（2026-10-12 用户反馈："加大坡度，减小摩擦"）：8.0 → **12.0**、0.45 → **0.25**。12° 比真机的 6.5° 陡得多——本作是慢速弹球，需要更明显的下滑才推得动节奏。

## 11. `Esc` 分层与全局三键

- `Esc`：主菜单 → hub；游戏中 → 暂停菜单（`RESUME` / `RESTART` / `QUIT TO MENU`）；暂停菜单 → 继续；结算 → 主菜单。
- **暂停时树真的暂停**，且菜单节点设 `process_mode = WHEN_PAUSED`（跟着一起暂停的菜单是谁也按不动的）。
- **`P`（只读）**：把**两类碰撞几何分开画**——Jolt 管的静态体用亮黄 `#FFE94A` 线框，**flipper 的胶囊判定范围用另一个颜色，且同时画上一帧姿态**（扫掠区间一眼可见）；再加球的速度矢量。纯诊断，不改玩法。
- **`[`（作弊）**：flipper 长度 ×`flipper_length_scale`——挡板更长，更容易救球。
- **`]`（超级作弊）**：**永不掉球**——球越过 drain 线时弹回台面（**不送进发射道**，那样还得重新发射一次，反而更烦），球的**纹样变荧光绿 `#00E676`**（画在球身上，因为被接管的是球）。
- `[` 与 `]` **每局开始 / 重开时复位**——实现上不需要专门写一行：**新一局就是新建一张台面**，台上的一切随之归零。
- **暂停时 root 根本不处理输入**（它没设 `WHEN_PAUSED`，树一暂停它就安静了），由暂停菜单自己接管 Esc。所以 `Esc` 的分层**不需要在 root 里判断"我是不是在暂停中"**——这一层由引擎的 `process_mode` 替我们判了。

## 13. 风险 / TODO

1. **⚠️ flipper 冲量的量级完全未知**：`flip_angular_speed = 14` 配 `length = 2.0`，**尖端**线速度 = ω·L = **28 单位/s**，内侧（0.8）约 11。球被打出去的增量是 `(1 + restitution) × (v_surf + 球沿法线的速度)`——**球越快这一击越猛**，所以 `max_speed = 64` 会被经常吃到。**梯度是设计要的**（尖端打得更远），但绝对量级是**纸面推算**——真机球只有 80 g，而本作球的质量与惯量都是自己定的。**打出来是"啪"还是"被风吹走"只有上手才知道。**若太软，先怀疑 **③ 冲量公式里的相对速度方向**，再怀疑角速度。
2. **⚠️ 判定圈放大的保守性**：`contact_slack = 1.15` 把接触判定圈外扩约 12%。缓解：只在 `vn < 0`（真的在靠近）时才施加冲量——**"判定接触"与"施加冲量"是两件事**，多报接触不会多给力。若"球在挡板边上被莫名弹开"仍能感觉到，把 slack 往 1.0 收。
3. **两套物理并存的调试**：`P` 叠加层的**两色分工**就是为这条准备的。出问题时先看颜色判断是谁干的，别在两个系统之间瞎猜。
4. **球的滚动量**：`angular_damp = 0.05` / `friction = 0.15` 是实机改过**两轮**的值。若球**停不下来**（一路滚进 drain），调大 `linear_damp`；若**转得不够**、还是像在滑，把 `friction` 再提——**但别低于 0.082**，那是 16° 下纯滚动的底线（`(2/7)·tan θ`）。
5. **`max_contacts_reported` 太小会漏接触**：球同时贴着多处（墙角）时需要更多槽位。初值 8，若发现有撞击偶尔不计分，先查这里。
6. **⚠️ 本节还没有具体数字**：Phase 1–3 每轮都由**用户实机跑过**，反馈已收敛进 cfg（车道加宽、提速、QUIT 改回 hub），但**没有人把实测数记下来**。下次实机顺手补：**flipper 的实际出射速度**、**球在 16° 台面上的稳态速度**、**满蓄力能否稳定进台面**。

## 14. 验收

### 可自动校验的（headless）

- `--import` 零 error / warning；`pinball.tscn` 与 `table.tscn` 可加载、无脚本错误。
- 全部 `class_name` 注册成功。
- `PinballLayout` 的几何自检：折线端点落在该落的地方（**drain 缺口与车道开口的宽度就是那两个端点之间的距离**）、无自交。
- 存档三态：文件不存在 / 内容损坏 / version 不符，三种都回退空存档且不崩；后两种要能被界面读出来。

### 只有人能定的

- flipper 的**手感**（软硬、行程快慢）与"尖端打得更远"是否成立；
- 球滚得像不像弹珠（`angular_damp` / `friction` / `linear_damp` 三者）；
- **倾斜角 16° 的节奏**对不对（太陡会一直往下冲，太缓会闷）；
- 三个保险杠的位置顺不顺手、两个弹弓贴不贴得住斜壁（球会不会卡在某个角落死循环）；
- 蓄力时间 1.1 s 与发射速度区间的手感；**满蓄力能不能稳定进台面**；
- 菜单 / 暂停 / 结算的排版与焦点；**存档退出重进**；两个作弊键。

### 导出后必做（教训 37 / 38 / 39）

- **导出前先重启 Godot 编辑器**，否则它会用内存里的旧预设覆盖 `include_filter`。
- 过滤器需要 `"*.cfg, *.txt"`——**`pinball.cfg` 是没导入器的裸文件**，本地跑得好好的导出版会静默用空配置。
- 导出后**在包内查 `pinball.cfg` 的内容**，并实机玩一局。
