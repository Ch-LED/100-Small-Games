## 3. 结构模型（场景即架构，CONSTITUTION 五点五）

```
pingpong.tscn  (PingPong, Control, game.gd)
├─ Background (ColorRect)
├─ Playfield (Node2D)
│   ├─ PaddleLeft / PaddleRight   (scenes/paddle.tscn 实例)
│   ├─ WallTop / WallBottom       (scenes/barrier.tscn 实例)
│   ├─ ZoneLeft / ZoneRight       (scenes/barrier.tscn 实例)
│   └─ Ball                       (scenes/ball.tscn 实例)
├─ CenterLine (ColorRect)
├─ Scoreboard (Label)
├─ Ai (Node, ai.gd)
└─ Audio (Node, pong_audio.gd)
```

- **实体根节点 = `Area2D`**：每个实体的视觉 `ColorRect` 是该 Area2D 的**子节点**、挂在原点上，随父自动移动——**不需要逐帧同步代码**。几何在 `setup()` 里按 cfg 生成（CollisionShape + ColorRect 尺寸）。
- **`setup()` 必须在 `add_child()` 之后调用**：`@onready` 子节点只在节点入树后解析。
- 坐标单一：根 Control 与子 Area2D 均在视口逻辑坐标系；实体以中心定位，视觉 `position = -size/2`。
- 主场景里只有静态画面和实体骨架；`game.gd` 负责读 cfg、摆位置、接信号，不造结构。

### 碰撞解算（解析式，不走 area 信号）

球不再依赖 `area_entered`：`Area2D` 节点仅作为**几何持有者**（墙与球拍各暴露 `global_rect()`，球读它们的矩形做扫掠），`monitoring` 全部关闭。理由见 §4 与 DECISION_LOG 013——离散的进入信号在墙-拍夹角处会漏球。

球通过 `@onready` 命名兄弟引用拿到这些几何：`@onready var _paddle_left: PongPaddle = $"../PaddleLeft"`（同 PaddleRight / WallTop / WallBottom / ZoneLeft / ZoneRight），无字符串 group 常量、无自建信号网。

## 4. 实体逻辑

### Ball（ball.gd）——扫掠碰撞

- 常量速率、仅改方向：每物理帧把 `step = dir × speed × delta` 交给扫掠解算（`_sweep`），不直接位移。
- **扫掠（swept）解析解**：把球当半径 `_radius` 的圆，沿 `step` 对「上/下墙 + 左右拍」四个 AABB 做**连续碰撞**（Minkowski 展宽矩形 + slab 射线法），取最早接触的 `t`，移到接触点、按接触法线反射、再用**剩余距离**继续走——一帧内可连做多次（上限 `MAX_BOUNCES`）。
  - 由此**任何速度都不会穿隧**，且墙-拍夹角处法线取的是真实接触面（前脸 / 顶底面 / 角点），不再出现"从夹角漏出去"。
  - 接触法线由 slab 决定：横向 slab 命中 → 水平法线 `(±1,0)`；纵向 slab 命中 → 垂直法线 `(0,±1)`。
  - 每帧起始先 `_push_out_of_overlaps()`：球拍移动可能挤进球里，沿最浅面把球推出去并反射，保证解算不以"球埋在拍内"开局。
- **弧面手感（仅前脸命中保留）**：`|normal.x| > 0.5` 且命中对象是球拍时，法线绕轴旋转 `reflect_curve × edge`（`edge = clamp((ball.y − paddle.y)/half, ±1)`）再叠加 `random_deflect_deg` 随机角；并强制 `v.x` 朝场地侧，防旋转把球推回拍内。顶/底面命中是纯镜像。
- **速度递增**：每次接触球拍 `speed ×(1 + speed_boost_per_hit)`（默认 +5%）；发球重置为 base `speed`。
- ⚠️ **反射必须用 `Vector2.bounce(n)`，不是 `reflect(n)`**：Godot 的 `reflect` 是"关于直线镜像"（`2n(n·v) − v`），表面反弹是 `bounce`（`v − 2n(n·v)`），两者互为相反数。用错会让纵向分量不翻转、球卡在壁上（剩余位移被丢弃）。
- **反弹角硬约束**：`_enforce_min_angle()` 把方向拉回「与竖直方向锐角 ≥ `min_bounce_angle_from_vertical_deg`（默认 40°）」的锥面外，杜绝近垂直的墙间死循环；因每次反弹都过这道口，整局中该不变式恒成立（`|dir.x|` 因此恒 ≥ sin40° ≈ 0.64，无需 `min_dir_x` 之类单独兜底）。
- **进球**：球的边缘越过球拍后的门线（由 `ZoneLeft/ZoneRight` 的矩形给出）→ 发 `scored(side)`，`game.gd` 复位。左门线 = 玩家得分 +1，右门线 = 电脑得分 −1。
- `set_center` 置中停球；`game.gd` 用 `serve_pause` 静置后调 `launch_random()` 随机发向。

### Paddle（paddle.gd）
- 视觉矩形，速度钳制移动：每帧朝 `_target`（−1/0/1）方向以 `max_speed` 移动，位置限制在场内垂直范围（含到边界的距离配置）。
- 输入在 `game.gd` 汇总：`wasd_up||arrow_up` → 目标上，反之亦然；只下发给右拍（玩家）。
- AI 不走 `set_target`，而是每帧调 `ease_toward(ball.y, t)` 直接插值定位。

### 电脑 AI（ai.gd）——指数插值追踪

- 每物理帧取 `dy = ball.y − paddle.y`；`|dy| ≤ dead_zone` 时不动（避免抖动）。
- 否则按 `t = 1 − exp(−follow_rate × delta)` 把球拍朝球的 y 插值过去。用指数形式而不是定权重 lerp，是为了让**每秒逼近的比例与帧率无关**。
- 调参只看 `follow_rate`：越大追得越紧、越小越好打。写进 `paddle.ease_toward(target_y, t)`，与玩家的 `set_target` 并存——玩家走离散方向，AI 走插值。

### Game 对局（game.gd）
- 初始 `serve`：球置中静止 → 2s `SceneTreeTimer` → 随机左右方向 `launch`（同时播发球音）。
- `scored(side)`：中央 `Label` 净分 `+= 1 / -= 1`；播得分音；球回中、静置 2s 再随机发向（重复、无限）。
- 场地尺寸变化：重算墙位、四边、中缝、球/拍边界 clamp。

### 音效（pong_audio.gd）—— 程序化

**不使用音频素材**：启动时合成 PCM 到 `AudioStreamWAV`（22.05kHz / 16-bit / 单声道），播放走 6 槽 `AudioStreamPlayer` 池。合成 helper（`_square` / `_cadence` / `_envelope`）与 `02-space-invaders/scripts/space_audio.gd` 同源——**后续可考虑抽到 `plugins/`**。

| 事件 | 音色 | 触发 |
| --- | --- | --- |
| 击拍 | 方波 520Hz / 0.06s，`pitch_scale` 随球速（球速 ÷ base speed，钳 0.85–2.2） | `PongBall.paddle_hit(speed)` |
| 撞墙 | 方波 240Hz / 0.05s | `PongBall.wall_hit` |
| 得分 | 两音下行 [660, 440] Hz | `PongGame._on_scored` |
| 发球 | 方波 320Hz / 0.08s | 发球瞬间 |

球**不直接引用音频**：反弹时发 `paddle_hit(speed)` / `wall_hit` 信号，由 `game.gd` 接给 `PongAudio`（与既有 `scored` 同一模式）。

### 6.1 超级作弊 `]`（`super_cheat_toggle`）

- **机制**：`ball.gd::_steer_home()` 只在 `_vx > 0`（球正朝玩家这一侧飞）时生效——此时它能碰到的只剩玩家拍与上下墙——把 `(_vx, _vy)` 朝 `_paddle_right` 的中心 `slerp` 一个 `[cheat] homing_rate` 的权重。**只改方向不改速度**，本作"球速恒定"的不变式不动。
- **表现**：`_apply_visual_color()` 在开着时用 `SUPER_COLOR`（`#00E676`）替换球色，**保留原有的 `color_alpha`**（本作球体是半透明的，不能因为变色丢掉这一点）。
- **复位**：本作是无限对局、没有"局"的概念，所以**不复位**——它与 `P` 同一性质的状态开关。
- **实测（断言脚本，跑完即删，10 项全过）**：关着时一发固定来球会被得分；**走真实的 `_unhandled_input` 开关**后，同一发球被拍子打回来；再关一次，失分与配色**双双还原**。
