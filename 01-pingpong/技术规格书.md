## 3. 结构模型（场景即架构，CONSTITUTION 五点五）

```
pingpong.tscn  (PingPong, Control, game.gd)
├─ Background (ColorRect)
├─ Playfield (Node2D)
│   ├─ PaddleLeft / PaddleRight   (scenes/paddle.tscn 实例)
│   ├─ WallTop / WallBottom       (scenes/barrier.tscn 实例)
│   ├─ ZoneLeft / ZoneRight       (scenes/barrier.tscn 实例)
│   └─ Ball                       (scenes/ball.tscn 实例)
├─ CenterLine (ColorRect)
├─ Scoreboard (Label)
└─ Ai (Node, ai.gd)
```

- **实体根节点 = `Area2D`**：每个实体的视觉 `ColorRect` 是该 Area2D 的**子节点**、挂在原点上，随父自动移动——**不需要逐帧同步代码**。几何在 `setup()` 里按 cfg 生成（CollisionShape + ColorRect 尺寸）。
- **`setup()` 必须在 `add_child()` 之后调用**：`@onready` 子节点只在节点入树后解析。
- 坐标单一：根 Control 与子 Area2D 均在视口逻辑坐标系；实体以中心定位，视觉 `position = -size/2`。
- 主场景里只有静态画面和实体骨架；`game.gd` 负责读 cfg、摆位置、接信号，不造结构。

### 检测方向（单向）

| 节点 | monitoring | monitorable | 说明 |
| --- | --- | --- | --- |
| Ball | true | false | 唯一监听方，靠自带 `area_entered` |
| Paddle / Wall | false | true | 被动可被球感知 |

Ball 靠**命名兄弟节点引用**区分命中对象：`@onready var _paddle_left: Area2D = $"../PaddleLeft"`（同 PaddleRight / WallTop / WallBottom / ZoneLeft / ZoneRight），碰撞回调内以 `area == 节点` 判断，无字符串 group 常量、无自建信号网。game.gd 先建好全部命名实体，再添加球，保证其 @onready 引用可解析。

## 4. 实体逻辑

### Ball（ball.gd）
- 常量速率，仅改方向：`_physics_process` 里 `position += dir * speed * delta`。
- **每次碰到球拍，速度 ×(1 + `speed_boost_per_hit`)**（默认 +5%，cfg 可配）；每次发球速度重置为 base `speed`。
- 不做穿透检测（用户明确）：碰撞完全信任 `area_entered` 逐物理帧检测。
- `_on_area_entered(area)` 按节点引用相等分流：
  - `area == WallTop/Bottom` → 纵向反射。
  - `area == PaddleLeft/Right` → **弧面反射**：接触命中相对拍心偏移量 `dy = ball.y - paddle.y`，命中点在拍高内 `t = clamp(dy / half)`（clamp ±1）；法线 `normal = (±1,0)` 绕轴旋转 `reflect_curve * t` 再叠加 `random_deflect_deg` 随机角；`dir = dir.reflect(normal)` 后归一化并强制远离拍面（`_set_dir_away_from`），兜底 `|dir.x| >= min_dir_x`、`|dir.y| <= 0.97`。
  - `area == ZoneLeft` → 玩家得分（左=电脑后方）；`ZoneRight` → 电脑得分。发 `scored(side)` 信号后 `game.gd` 复位。
- `set_center` 置中停球；`game.gd` 用 `serve_pause` 静置后调 `launch_random()` 随机发向。

### Paddle（paddle.gd）
- 视觉矩形，速度钳制移动：每帧朝 `_target`（−1/0/1）方向以 `max_speed` 移动，位置限制在场内垂直范围（含到边界的距离配置）。
- 输入在 `game.gd` 汇总：`wasd_up||arrow_up` → 目标上，反之亦然；只下发给右拍（玩家）。
- AI 不走 `set_target`，而是每帧调 `ease_toward(ball.y, t)` 直接插值定位。

### 电脑 AI（ai.gd）——指数插值追踪

- 每物理帧取 `dy = ball.y − paddle.y`；`|dy| ≤ dead_zone` 时不动（避免抖动）。
- 否则按 `t = 1 − exp(−follow_rate × delta)` 把球拍朝球的 y 插值过去。用指数形式而不是定权重 lerp，是为了让**每秒逼近的比例与帧率无关**。
- 调参只看 `follow_rate`：越大追得越紧、越小越好打。写进 `paddle.ease_toward(target_y, t)`，与玩家的 `set_target` 并存——玩家走离散方向，AI 走插值。

### Game 对局（game.gd）
- 初始 `serve`：球置中静止 → 2s `SceneTreeTimer` → 随机左右方向 `launch`。
- `scored(side)`：中央 `Label` 净分 `+= 1 / -= 1`；球回中、静置 2s 再随机发向（重复、无限）。
- 场地尺寸变化：重算墙位、四边、中缝、球/拍边界 clamp。

## 5. 配置文件 `pingpong.cfg`（ConfigFile/INI，含注释）

```ini
[field]
bg_color="808080"           ; 50% 灰
[center_line]
color="FFFFFF"
alpha=0.45
width=8.0
[ball]
radius=11.0
speed=520.0
color="FF8A5C"
color_alpha=0.85
speed_boost_per_hit=0.05    ; 每碰拍 +5%
serve_pause=2.0
serve_min_deg=12.0
serve_max_deg=32.0
reflect_curve=0.55          ; 命中偏移→法线旋转(rad)
random_deflect_deg=4.0
min_dir_x=0.30
[paddle]
width=16.0
height=120.0
edge_distance=36.0
max_speed=900.0
left_color="2E6BD6"
right_color="E0433A"
[ai]
follow_rate=6.0             ; 指数追踪速率，越大越紧
dead_zone=6.0
[scoreboard]
font_size=300.0
alpha=0.38
```

所有颜色以 6 位 hex 存，加载时 `Color.html` 解析。代码内**零调参魔法数**。

## 6. 输入（project.godot `[input]`，项目级、全项目共享）

定义四动作（键位彼此独立、可单独复用，游戏内 fallthrough 合并）：

| 动作 | 键 |
| --- | --- |
| `wasd_up` | W |
| `wasd_down` | S |

| `arrow_down` | ↓ |

## 7. 设计风险 / TODO

| 事项 | 优先级 | 缓解 |
| --- | --- | --- |
| 不做穿透检测（用户明确） | - | 信任逐物理帧 `area_entered`；若未来出现漏检再单独评估 |
| Control 作 Area2D 子节点的定位 | 低 | 视觉以实体原点居中 `position=-size/2`；首验通过后固化 |
| 纯垂直/水平死循环 | 低 | `min_dir_x` + `|dir.y|≤0.97` 兜底 |
