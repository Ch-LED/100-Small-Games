# 02-space-invaders — 技术规格书

> 依据：`02-space-invaders/策划案.md`。结构样板沿用 pingpong（DECISION_LOG 010）。与实现冲突时修正实现。

## 1. 运行与返回

- 编号 02，slug `space-invaders`，主场景 `space-invaders.tscn`（游戏根）。
- 只从 hub 桌面进入；游戏中按 `Esc` 调 `GameRouter.back_to_hub()`（开始界面按 Esc 同样返回）。
- 视口 1280×720，素材 16×8 按 `scale.factor`（默认 4）整数倍放大，纹理过滤 **NEAREST**（`project.godot` 的 `rendering/textures/canvas_textures/default_texture_filter=0`）。坐标一律用像素单位。
- **拉伸**：`canvas_items + keep`（DECISION_LOG 017）——逻辑区恒为 1280×720，非 16:9 窗口留黑边。这样 Control 层的 rect 与 `SpaceField.SIZE` 恒等，"游戏逻辑按写死 1280×720、Control 跟随 viewport" 的两套基准不会错开。

## 3. 素材切分

- `sprites.json` 的 `meta.frameTags` 是权威映射；按 tag 的 `from..to` 帧号取 rect。
- **tag 名须与 aseprite 完全一致**（拼写/大小写），查不到会返回空矩形导致精灵全透明。当前 tag 表：

| tag | 帧 | 用途 | 裁剪后实际尺寸 |
| --- | --- | --- | --- |
| `player` | 0 | 玩家 | 12×7 |
| `jelly` | 1–2 | 水母 10pt | 12×8 |
| `claude` | 3–4 | claude code 20pt | 12×8 |
| `squid` | 5–6 | 鱿鱼 40pt | 8×8 |
| `UFO` | 7 | 飞碟 | 16×7 |
| `plaz` | 8–11 | 敌人能量弹 | 2×5 ~ 3×5 |
| `drat` | 12–13 | 敌人飞镖弹 | 3×4 |
| `lazer` | 14 | 玩家激光弹 | 1×4 |
| `frot_sqr` | 15–18 | 掩体方形瓦片（4 级损伤） | 6×6 |
| `frot_tri` | 19–22 | 掩体三角瓦片（4 级损伤） | 4~6 × 5~6 |
| `space_1/2/3` | 23–25 | 背景星点瓦片 | 6×6 |
| `space_4` | 26 | 背景纯色瓦片（大面积打底） | 6×6 |
| `explode` | 27 | 爆炸特效 | 11×8 |

> ⚠️ 掩体的 tag 在 aseprite 里拼作 **`frot_sqr` / `frot_tri`**（不是 `fort_*`），按原样使用。

- **按内容裁剪（trim）**：原始帧统一是 16×8 格子，但美术只占其中一部分。
  - **优先用 aseprite 的 Trim Sprite 导出**：`"trimmed": true` 时 `frame` 已是裁剪后的紧凑区域，直接采用，**不扫像素**。
  - 未启用 trim 时回退到启动扫一次 alpha 边界（`_trim()`）。
  - 解析帧时**按迭代序号索引，不解析 key**——key 格式会随导出选项变化（`"sprites 0.aseprite"` / `"sprites #jelly 0.aseprite"`），而 aseprite 始终按 sheet 顺序输出。
  - 接口：`content_rect(tag, index)`（精灵/碰撞用）、`content_size(tag, index, factor)`（放大后尺寸）、`cell_size(factor)`（原始 16×8 格子，**仅用于方阵间距**）。
- 实体视觉 `Sprite2D` + `AtlasTexture`（`filter_clip = true` 防渗色），挂 Area2D 之下、居中；碰撞 shape 用 `content_size`；放大 `Sprite2D.scale = factor`。
- **场地**：逻辑分辨率 1280×720。所有玩法边界统一走 `SpaceField.PLAY_RECT`（方阵横向居中与触边、玩家左右 clamp、掩体分布、UFO 出入场）。侧边黑幕机制保留（`_build_side_masks`，当 `SIDE_RATIO > 0` 时在 playfield 之后自动铺两块黑条），**当前 `SIDE_RATIO = 0`，即全屏无遮罩**；想收窄只需改这一个常量。
- **背景瓦片混合**：`game.gd` 的 `BACKGROUND_WEIGHTS` 决定抽取比例——`space_4`（纯色）0.70 打底，`space_3` 0.20、`space_1` 0.06、`space_2` 0.04 作星点。权重在**实际存在的 tag** 间重新归一化，每个瓦片随机 90° 旋转。
- **素材改动后务必确认导入**：覆盖 `sprites.png` 后 Godot 未必自动重新导入，需删除同目录 `sprites.png.import` 再跑 `godot --headless --path . --import`；缓存是否更新可对比 `.godot/imported/*.md5` 里的 `source_md5` 与源文件 md5。

## 4. 结构模型与场景树（场景即架构，CONSTITUTION 五点五）

```
space-invaders.tscn  (SpaceInvaders, Control, game.gd)
├─ Background (Control)
│   ├─ Base (ColorRect)                深蓝底
│   └─ Tiles (Control)                 三种 space_* 瓦片拼铺（代码填）
├─ Playfield (Node2D)
│   ├─ Player      (scenes/player.tscn)
│   ├─ EnemyGrid   (Node2D, enemy_grid.gd)
│   ├─ Shields     (Node2D)            掩体从数据生成挂这里
│   ├─ Bullets     (Node2D)            双方子弹挂这里
│   └─ UfoSlot     (Node2D)            飞碟挂这里
├─ Hud (Control, hud.gd)
│   ├─ ScoreLabel (Label)
│   └─ LivesBox   (HBoxContainer)
├─ Overlay (Control)
│   └─ Box ├─ Title ├─ Rows ├─ Message
└─ Audio (Node, space_audio.gd)
```

**静态结构在场景里，只有数据内容由代码填**：星点瓦片、敌人、子弹、掩体瓦片、分数行是动态的；其余（背景框、HUD 框、结算框、各挂点）都是场景节点。

实体场景：`scenes/enemy.tscn`、`bullet.tscn`、`player.tscn`、`ufo.tscn`、`fort_tile.tscn`，各含 `Collision`(CollisionShape2D) + `Sprite`(Sprite2D)，纹理按 tag 在 `setup()` 里切。

> ⚠️ **生成实体一律 `SCENE.instantiate()`，禁止 `InvaderXxx.new()`。** 裸脚本实例没有场景里的 `Collision`/`Sprite` 子节点，`@onready` 引用为 `null`，`setup()` 里首行 `_collision.shape = ...` 就会报 `Invalid assignment ... on a base object of type 'Nil'`。同理对 `add_child()` 与 `setup()` 的先后顺序敏感（见下）。

> ⚠️ **`setup()` 必须在 `add_child()` 之后调用**。`@onready` 子节点只在节点入树后解析；若先 setup 再入树，`_collision` 会是 `null`。同理，容器（如 `InvaderShield`）要先入树，它内部再 `add_child` 的瓦片才能解析自己的子节点。

## 5. 系统职责

### Game（game.gd）
- 状态机：`TITLE` → `PLAYING` → `DYING` → `OVER`。
  - `TITLE`：Playfield 冻结、显示开始画面（标题 + 分值说明），空格开局。
  - `DYING`：最后一条命被击中时——玩家贴图换成 `explode`、战场冻结、子弹清空，等 `player.death_pause`（默认 1s）后转 `OVER`。
  - `OVER`：显示结算画面，空格重开。
- 敌人开火频率由 `enemy_fire.fire_fail_chance` 控制（当前 0.7，即每次尝试约 30% 成功）。
- `_advance_wave()` 必须 `call_deferred()`：它在子弹的物理回调链上被触发，直接重建方阵会在物理查询 flush 期间改动物理服务器。另用 `_wave_pending` 防止同帧多颗子弹清掉最后一行时重复触发。
- **开火锁定**：每关开头 `player.fire_lock`（默认 0.5s）内忽略玩家开火输入，`_start_game` 与 `_advance_wave` 都会重置。
- **调试作弊键 `P`**（项目级动作 `debug_toggle`，与 03-pacman 共用同一键）：切换 `_fire_cheat`；开启后 `_try_player_fire` 跳过单发限制，可同屏多发。纯调试用，不参与正式玩法。
- 持有分数、残机、关卡号；对外暴露 `add_score(n)`、`lose_life()`、`on_wave_cleared()`。
- 每帧检查结束条件：残机归零（走 DYING 流程）、或方阵最低行触到玩家线**再提前一整行**（`_grid.row_step_y()`）——在贴图真正叠上之前就判负。

### Player（player.gd）
- 左右移动（限速、受屏幕边界约束），高度固定在底部 `player.bottom_margin`。
- **开火**：空格**按住**即持续尝试发射；场上存在自己的子弹时无法再发（单发限制，`P` 作弊键可解除），实际射速由子弹存活时间决定。
- **只在被击中重生时**进入 `invuln_time` 无敌（闪烁提示）——开局与每关换关都不给无敌，避免无谓的闪烁。
- `explode()`：最后一条命被击中时把贴图换成 `explode` 并取消闪烁无敌，供 Game 的 `DYING` 阶段使用。
- `lose_life()`：扣 1 残机，原地复活并 `invuln_time` 无敌（闪烁提示）。

### EnemyGrid（enemy_grid.gd）
- 生成 5×11：行 0 = squid，行 1–2 = claude，行 3–4 = jelly。横向按 `PLAY_RECT` 居中。
- **起始高度**：每清一关，方阵起手就比上一关低 `level_shift_rows`（默认 1 整层 = `cell.y + row_gap`）；但**距掩体顶边至少 `level_clear_rows`（默认 2）层**——再低就夹住不再下降（`_spawn_top` 取 `min(desired, lowest_allowed)`）。
- **tick 驱动**：`tick_period` 按 §6 曲线推进；到点整阵横移 `step_x`，触 `PLAY_RECT` 边界则**下移一整层**（`cell.y + row_gap`，不是固定的 step_y）并反向。
- **动画每 tick 切换一次**（不再按固定 `anim_fps`），所以方阵越快、摆动越快。
- 开火：**每 `fire_interval` 个 tick 抽一次**，选最前排（逐列取最靠下者）随机一只，按 `energy_ratio` 抽弹种，按 `fire_fail_chance` 判失败。
  - 期望保真：旧逻辑每 tick 以 0.70 失败率尝试（0.30 成功/tick）；改为每 3 tick 一抽后，`fire_fail_chance=0.10`（0.90 成功/roll × 1/3 roll/tick = 0.30 成功/tick）。改动该值时按此换算。
- 提供 `alive_count()`、`lowest_row_y()` 供 tick 曲线与结束判定用。

### Enemy（enemy.gd）
- 单只：记录 `kind`（squid/claude/jelly）与分值；两帧动画。
- 被玩家子弹命中 → 播放 `explode`、加分、`queue_free()`。

### Bullet（bullet.gd）
- `kind`：`lazer`（玩家，单帧）／`plaz`（敌人能量，四帧）／`drat`（敌人飞镖，两帧）。
- 直线飞行；出界或命中后销毁。**不做穿透**；掩体瓦片未被击穿前挡住子弹（子弹消失，瓦片 -1）。
- **碰撞盒下限**：裁剪后弹丸最细只有 1px 宽，高速下会直接穿过目标。碰撞盒尺寸取 `max(裁剪尺寸, [bullet] min_width/min_height)`，默认下限 16×16 px。

### Ufo（ufo.gd）
- 按 `interval_min..max` 间歇从一侧横穿顶部；被击中 → **跳分数（50–300 随机），不播爆炸**，随即消失。

### Shield（shield.gd + 瓦片）
- 每掩体由 6×6 瓦片网格拼成（形状见 §8），顶部两角用 `frot_tri`，其余 `frot_sqr`。
- 每瓦片 `tile_hp = 4`；受击 -1 并切换损伤帧（`hp` 1→4 对应 tag 内 index）；归零则移除该瓦片。
- **被敌机方阵压到即整块吞掉**（瓦片直接移除）。

### SpaceAudio（space_audio.gd）—— 程序化音频

**不使用任何音频素材**，启动时用代码合成 PCM 到 `AudioStreamWAV`（22.05kHz / 16-bit / 单声道），播放走一个 8 槽的 `AudioStreamPlayer` 池以支持重叠。

| 事件 | 音色 | 触发点 |
| --- | --- | --- |
| 背景行进音 | 方波，4 个音高（110 / 138.59 / 164.81 / 220 Hz），每 tick 换一个 | `EnemyGrid.ticked(count)` |
| 玩家开火 | 方波快速下滑 900→220 Hz | `_try_player_fire` |
| 敌人被击毁 | 方波下滑 420→160 Hz | `_on_enemy_killed` |
| 玩家受伤 | 白噪声衰减 0.35s | `_on_player_hit` |
| 飞碟出场 | 660/990 Hz 交替颤音 | `_spawn_ufo` |
| 飞碟击毁 | 长下滑 1300→180 Hz | `_on_ufo_destroyed` |
| 游戏结束 | 四音下行（392/330/262/196 Hz） | `_end_game` |

所有波形都带短淡入淡出包络，避免爆音。要换音色只需改这个文件里的合成参数，或整体替换成外部素材（接口不变）。

### Hud（hud.gd）
- `ScoreLabel` / `LivesBox` 是**场景节点**（锚点写在 `.tscn` 里，CONSTITUTION 五点五）；脚本只经 `%ScoreLabel` / `%LivesBox` 填内容，不再用代码新建。
- 左上：分数，像素字体、**六位补零**（`%06d`），位置与上/右边距走 `hud.margin`。
- 右上：残机（用 `player` 小图标 ×N）。
- 字体见 §9（Press Start 2P + `PixelFont`）。

## 6. tick 加速曲线（时间为主、数量为辅）

```
threshold = fast_at_rows * cols              # 默认 2*11 = 22
by_count  = clamp((initial_count - alive) / (initial_count - threshold), 0, 1)
by_time   = clamp(elapsed / time_to_max, 0, 1)
open      = clamp(descended_span - level_open_delay, 0, 1)   # 见下
progress  = clamp(open + count_share * by_count + time_share * by_time, 0, 1)
tick_period = lerp(level_slow, level_fast, progress) * per_level_speedup^(level-1)
```

- **开局进度 `open`**：把曲线看成"方阵从起手位置一路下探到掩体线"的**速度–位置**关系。某关起手就低了一层，等于已经把这段曲线**走了一段**，所以要按该位置的进度开局（而不是像原来每关都从 `progress=0` 重来）；再用 `level_open_delay` 把曲线**整体沿时间轴正推**一段做削减，开局才不会过陡。
  - `descended_span = (起手行 − 一级起手行) / (掩体线 − 一级起手行)`，即已下探的比例。
  - `level_open_delay`（默认 0.08，progress 单位）即"削减量"；调大 = 开局更慢。
- `count_share=0.25`、`time_share=0.75`：消灭敌人会加快，但**时间因素占主导**，避免残敌少时火力骤增。
- **约束**（防止数量因素喧宾夺主）：一关内数量项的最大贡献不得超过 **20 秒**时间项的贡献，即
  `count_share <= time_share * (20 / time_to_max)`。当 `time_to_max=60` 时上限恰为 `0.25`。
- `elapsed` 每关重置（`spawn()` 里清零）；`time_to_max` 默认 60s（时间加成刻意放缓）。
- 进入下一关 `level += 1`，基准整体更快。

## 8. 掩体形状（4×3 瓦片网格）

`S`=方瓦片，`T`=顶角三角（斜边朝外），`V`=门洞三角（斜边朝内），`.`=空。

```
T S S T
S V V S
S . . S
```
- 整体 96×72 px（瓦片 6px × factor 4），每掩体 10 块瓦片。
- 源三角（`frot_tri`）实心在左上角：
  - `T` 顶角 → **垂直翻转**（左侧再水平翻转），顶部向内收拢形成外圆角。
  - `V` 门洞 → **保持原方向**（右半边水平翻转），门洞向下张开成梯形。

## 9. 字体

- 采用 **Press Start 2P**（SIL OFL 1.1，可自由分发），置于跨游戏共享池 `assets/fonts/PressStart2P-Regular.ttf`。
- 由工具类 `PixelFont` 统一提供：`antialiasing=NONE` / `hinting=NONE` / `subpixel_positioning=DISABLED`，保证像素硬边。
- 字号取 **8 的整数倍**（8/16/24/32…）最清晰。

### 9.1 超级作弊 `]`（`super_cheat_toggle`）

- **机制**：`bullet.gd` 原来只沿 `_dir`（上下）走，现在走一个 `_direction` 向量（默认就是 `(0, ±1)`，所以**未开作弊时行为不变**）；`set_homing(fleet, rate)` 之后每帧把 `_direction` 交给**共享插件 `plugins/homing`** 掰向 `EnemyGrid.nearest_alive_to()`，**方阵清空就自动改回直飞**。
- **谁给的目标**：`_fleet` 由**生成子弹的那一方**（`game.gd::_try_player_fire`）在 `_super_cheat` 为真时交进来，子弹自己不去满树找。**只有玩家子弹会被交给它**，敌人子弹不受影响。
- **⚠️ 顺带补的洞**：`_is_offscreen()` 原来只看上下——直线子弹永远不会从侧面飞出，**会拐弯的子弹会**，于是会变成永不释放的孤儿节点。补上左右两侧。
- **表现**：`Sprite2D.modulate` 直接置 `SUPER_COLOR`（`#00E676`）。
- **旋钮**：`[cheat] homing_rate`（每秒转多少）。
- **复位**：`_start_game()` 里清零。
