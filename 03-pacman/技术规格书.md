### 2.2 迷宫瓦片 `assets/maze_tiles.png`（tilemap 方案）

迷宫改用**自动拼接瓦片**，这样你可以做变体（换配色、换线宽）而不动布局数据。

**规格**：一张 **4×4 网格**的图，每格 16×16（整图 64×64），共 16 个瓦片。

**索引规则**：瓦片索引 = 4 位掩码，位序为 **上/右/下/左**。

```
bit 0 = 上方是通路 → 本格要画上边线
bit 1 = 右方是通路 → 画右边线
bit 2 = 下方是通路 → 画下边线
bit 3 = 左方是通路 → 画左边线
```

只有**墙格**参与拼接；判定邻居是否"通路"（通路 = 非墙、含隧道口）。

**图上的摆放位置**：`列 = 掩码 % 4`，`行 = 掩码 / 4`（左上角为索引 0）。

| 索引 | 掩码 | 上右下左 | 形状 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 0000 | · · · · | 空白 | 墙格四面都被墙包围（纯内部，通常全透明） |
| 1 | 0001 | ● · · · | ╷ | 只有上方连线（下端点） |
| 2 | 0010 | · ● · · | ╶ | 只有右方连线（左端点） |
| 3 | 0011 | ● ● · · | └ | 右下角 |
| 4 | 0100 | · · ● · | ╵ | 只有下方连线（上端点） |
| 5 | 0101 | ● · ● · | │ | 竖线 |
| 6 | 0110 | · ● ● · | ┌ | 右上角 |
| 7 | 0111 | ● ● ● · | ├ | T 形（缺左） |
| 8 | 1000 | · · · ● | ╴ | 只有左方连线（右端点） |
| 9 | 1001 | ● · · ● | ┘ | 左下角 |
| 10 | 1010 | · ● · ● | ─ | 横线 |
| 11 | 1011 | ● ● · ● | ┴ | T 形（缺下） |
| 12 | 1100 | · · ● ● | ┐ | 左上角 |
| 13 | 1101 | ● · ● ● | ┤ | T 形（缺右） |
| 14 | 1110 | · ● ● ● | ┬ | T 形（缺上） |
| 15 | 1111 | ● ● ● ● | ┼ | 四向全连 |

**画法建议**：线条画在格子的**边缘**（上下边线贴在 y=0 / y=15，左右边线贴在 x=0 / x=15），这样相邻墙格之间自然接上，形成经典的双线走廊。你可以在每条边线上做**双线**（内描边）来贴近原作观感。

另外单独提供 1 个瓦片：

| 文件 | 内容 |
| --- | --- |
| `assets/ghost_door.png` | 幽灵屋的门，16×16，画成一条横向的淡色栏杆 |

### 2.3 图层导出方式

精灵表按**角色分图层**导出（每个图层一组 tag），例如 `pacman` 图层含 `right` / `up` / `down` 三个 tag。代码侧会按「图层名 + tag 名」定位，所以：

- **图层名**用角色名：`pacman` / `ghost_body` / `ghost_eyes` / `fruit` / `pellet`
- **tag 名**用状态或方向：`right` / `up` / `down` / `death` / `blue` / `flash` / `cherry` …
- 我用 `"<图层>_<tag>"` 组合成查找键，两边任意一侧改名都会明确报错，不会静默画错。

## 4. 结构模型（场景即架构）

所有结构都写在 `pacman.tscn` 里，代码只负责填数据和实例化实体场景。

```
Pacman (Control, game.gd)
├─ Background (ColorRect)
├─ Maze (Node2D, pacman_maze.gd)
│   ├─ World (TileMapLayer)      ← 逻辑层：真实格子，一瓦片一格，对齐格心
│   ├─ View  (TileMapLayer)      ← 视觉层：由 World 推导的双网格（错位半格）
│   ├─ Doors (TileMapLayer)      ← 幽灵屋门，对齐格心
│   └─ Pellets (Node2D, pacman_pellets.gd)  ← 豆子自绘层
├─ Playfield (Node2D)
│   ├─ Pacman (player.tscn 实例)
│   ├─ Ghosts (Node2D)           ← 四只 ghost.tscn 实例
│   └─ FruitSlot (Node2D)        ← fruit.tscn 实例
├─ Hud (Control, pacman_hud.gd)
│   ├─ ScoreLabel / ScoreValue / Lives
│   └─ HighLabel  / HighValue  / Fruits
├─ Overlay > Message
└─ Audio (pacman_audio.gd)
```

### 4.1 双网格分层（World / View）

- **World** 是唯一权威：一格一瓦片、与格子中心对齐，`is_wall()` 直接读它（`get_cell_source_id`）。**已烘焙进场景**，不再依赖运行时布局数据。
- **View** 完全由 World 推导：每个**角点**看交于它的 4 个 World 格子，按 4 位掩码选瓦片；图层整体**错位半格**，所以瓦片中心落在格子角上。
- 程序化步骤只剩 `_rebuild_view()` 这一处（World → View）。
- **坑**：TileMapLayer 把格子 `(c,r)` 的中心放在 `(c+0.5, r+0.5)`。所以 World 层偏移是 `0`，View 层才是 `-半格`。两层都减半格会把墙整体推偏半格，看起来"墙厚了一倍"。

### 4.2 TileSet

`assets/maze_tileset.tres`：7 个基础瓦片 + 10 个 **alternative tiles**（镜像/旋转变体）。双网格需要的 16 种组合全部来自资源，代码只有一张 `mask → (列, alternative)` 映射表。

```
mask 0→[0,0]  1→[1,0]  2→[1,1]  3→[2,0]  4→[1,2]
     5→[2,2]  6→[3,0]  7→[4,3]  8→[1,3]  9→[3,1]
    10→[2,3] 11→[4,2] 12→[2,1] 13→[4,1] 14→[4,0] 15→[5,0]
```

- **`transpose` 的坑**：它是沿主对角线翻转，作用在"下半"上得到的是**右半**。所以 `mask 5`（右半）用 `transpose`，`mask 10`（左半）用 `flip_h + transpose`——两者极易写反。

- 网格坐标 → 像素：`pixel = PacmanGrid.ORIGIN + cell * PacmanGrid.CELL`；`ORIGIN = (FIELD - MAZE_SIZE) / 2`，由 `PacmanGrid.configure()` 在启动时按 cfg 的 `cell_size` 算出。

## 5. 吃豆人

- **移动**：沿当前方向恒速前进，只在**格心对齐**时允许转向。
- **转向预输入**：按键后记为 `desired_dir`，每当经过格心就尝试转向；能转则转，不能则继续。
- **停止**：撞墙且无可用转向时停住。
- **吃豆**：所在格有豆即吃掉并加分。
- **隧道**：横向越过边界时从对面折返。
- **动画**：朝右/上/下各三帧循环；朝左用右向帧水平翻转。
- **死亡**：播放 `pacman_death`，约 1.2s，冻结其余实体，然后重生或结算。

## 6. 幽灵（四只）

四只共用一套状态机，差异在**目标格的计算方式**：

| 名字 | 颜色 | 追击策略 |
| --- | --- | --- |
| Blinky | 红 | 直接以吃豆人所在格为目标 |
| Pinky | 粉 | 目标为吃豆人前方 4 格（朝向其当前方向） |
| Inky | 青 | 以吃豆人前方 2 格为支点，相对 Blinky 位置做二倍向量取反 |
| Clyde | 橙 | 距离吃豆人 >8 格时直追，否则退回自己的角落 |

**共用规则**
- 目标格只决定**在路口选哪个方向**；幽灵不能掉头（除非状态切换）。
- 四只幽灵的"离屋条件"不同（按豆子计数依次放出）。
- **状态**：`CHASE`（追击）→ `SCATTER`（散开，各自回角落）→ 交替；`FRIGHTENED`（能量豆触发，随机转向、可变蓝、可被吃）；`EATEN`（回巢，只显示眼睛，速度加快）。
- **速度**：普通 / 惊恐 / 隧道 / 回巢各不同，且随关卡提升。

## 7. 豆子与水果

- 豆子由 §3 布局生成：`. → pellet`，`o → power_pellet`。
- 吃掉全部豆子 → 过关。
- 每关吃掉 **70 / 170** 颗时，在幽灵屋上方生成水果，限时 `fruit_lifetime` 秒后消失。

## 8. 关卡与难度

- 过关后 `level += 1`：幽灵基础速度提升、能量豆持续时间缩短、水果种类升级。
- 到达 `level_cap` 后难度封顶（不再继续变快）。

### 10.1 作弊键设计草案（待实现）

- 输入：`debug_toggle`（**已定为 `P`**，项目级输入映射，跨游戏共用的调试开关键）。
- 开启后每帧：
  - 在四只幽灵各自的**目标格**画一个对应颜色的方框；
  - 在幽灵当前所在路口画一个**方向箭头**（选中的方向）；
  - 可选：把 `CHASE / SCATTER / FRIGHTENED / EATEN` 状态用文字标在幽灵上方。
- 只读展示，**不改变任何 AI 行为**，保证调试观察的就是真实决策。

### 10.2 作弊键（`cheat_toggle` = `[`）——穿墙

- **机制**：`pacman_player.gd` 新增 `_can_enter(cell)`，三处原本直接问迷宫的判定（`_decide()` 两处、走格一处）改问它；开着作弊时它一律回答"能进"。**改的是吃豆人这一侧，不是迷宫**——`PacmanMaze.is_wall()` 一个字节没动，所以墙照画、幽灵照走它们的路。
- **只给地图不给安全**：穿墙不等于无敌，幽灵照样能抓住他（碰撞是位置判定）；这也让这个作弊更像"抄近道"而不是"关掉游戏"。
- **复位**：`_restart()`（开新局）与 `]` 一起清零。
- **实测（断言脚本，跑完即删）**：关着时选中的墙格不可进入；开着时可进入，**而迷宫自己仍然说那是墙**；再关一次又不可进入。

### 10.3 超级作弊键（`super_cheat_toggle` = `]`）——幽灵掉头逃跑

- **机制**：`pacman_ghost.gd::_pick_target()` 里多一个分支——开着作弊时，目标格返回**吃豆人在这只幽灵身上的镜像**（`cell() * 2 - pac`）。**瞄准一个人的倒影，就是在远离他**，而且它把"离得越近退得越快"这件事免费拿到了。
- **为什么不塞进 `State`**：追击与逃跑**共用其它所有规则**（路口选择、不许回头、幽灵屋纪律），这个开关只换"瞄准哪一格"——所以它是一个独立布尔 `super_flee`，`State` 一个字没动，四只幽灵的个性也原样保留。
- **表现**：`set_super_flee()` 立刻 `_refresh_look()`，**按键当帧就变绿**，不用等下一个动画步；能量豆的蓝是另一个状态，不受影响。
- **复位**：`_restart()`（开新局）清掉；**过关不清**——作弊按"局"复位，与 07-breakout 一致。
- **实测（断言脚本，跑完即删）**：关着时一只追击中的幽灵一秒内与吃豆人的间距 9 → 1；开着时同一只 9 → **25**。四只身体在切换时全部等于 `SUPER_COLOR`、再按一次全部还原；`_restart()` 清零。
