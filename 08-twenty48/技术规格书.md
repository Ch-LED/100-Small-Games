## 3. 结构模型（场景即架构，CONSTITUTION 五点五）

```
twenty48.tscn  (Twenty48, Control, game.gd)
├─ Background (ColorRect)                     米白底
├─ Board (GridContainer)                      ★ columns=4，由引擎排布 16 个格子
│   ├─ Cell0 (Panel) > Value (Label)
│   ├─ Cell1 (Panel) > Value (Label)
│   └─ … 共 16 组，row-major（下标 = row*4 + col）
├─ DebugDraw (Node2D, game2048_debug.gd)      只读读数（P）
├─ Hud (Control, hud.gd)
│   ├─ ScoreLabel / ScoreValue
│   ├─ BestLabel / BestValue
│   ├─ MaxLabel / MaxValue
│   └─ CheatLabel                             `NO SPAWN` 常驻指示
├─ Overlay (Control) > Title (Label) > Message (Label)
└─ Audio (Node, game2048_audio.gd)
```

### 3.1 ★ 棋盘用 `GridContainer`，16 个格子是**场景里的固定结构**

- **位置一律不由代码计算**：`Board` 是 `GridContainer`（`columns = 4`，行列间距由 `theme_override_constants/h_separation`、`v_separation` 从 cfg 设入），16 个 `Panel` 按 row-major 顺序挂在它下面，引擎负责排布。
- 代码只做两件事：给每个格子设 `custom_minimum_size`（= cfg 的 `tile_size`），以及按当前数值**换样式与文字**。
- **每格 = `Panel` + `Label`**：数值为 0 时用"空格样式"且不显示文字；有数值时换成对应颜色的圆角 `StyleBoxFlat` 并写上数字。**没有独立的"方块实体"节点池**——格子本身就是方块，落子只是换样式，没有增删节点的开销。
- 圆角靠 `StyleBoxFlat.corner_radius_*`（引擎自带的能力），不是拿 `ColorRect` 硬凑。
- 界面以外的访问一律 `@onready var _x: Type = $Path`（CONSTITUTION 五）。

## 4. 数据模型（`grid_model.gd`，`class_name Game2048Grid`）

**纯逻辑，`extends RefCounted`**——不碰场景树、不发信号，所以可以直接拿去跑断言（本作断言的重头就在这里）。

- `SIZE := 4`；`cells: Array[int]`，长度 16，row-major，`0` 表示空。
- `empty_indices() -> Array[int]`、`largest() -> int`、`is_full() -> bool`。
- `can_move() -> bool`：有空格，**或**存在水平/竖直相邻且相等的两块。
- **`slide(direction) -> Dictionary`**：返回 `{moved: bool, gained: int}`。
  - 对每一行/列：按**行进方向**把 4 格读成一条线（**下标 0 = 目的端**），压缩掉 0，再合并，然后按同样顺序写回。
  - 合并规则：相邻两块相等才合，合完**跳过两块**（所以每块一步内只合一次，`2 2 2 2` → `4 4`）。
  - `gained` 累加所有合并出的数值；`moved` 在**写回结果与读入不同**时为真——**这是"这一步是否有效"的唯一判据**。
  - 四种方向的读取顺序：`LEFT` 行 0→3、`RIGHT` 行 3→0、`UP` 列 0→3、`DOWN` 列 3→0。
- `spawn(rng, four_chance) -> int`：在空格里随机挑一个放 `2`（默认）或 `4`；**没有空格返回 -1**。
- `snapshot() -> Array[int]` / `restore(s)`：整盘拷贝，供断言与将来的撤销用。

## 5. 对局（`game.gd`，`class_name Twenty48Game`）

状态机 `State { TITLE, PLAYING, OVER }`：

- `TITLE`：空棋盘，`PRESS SPACE TO START`。
- `PLAYING`：读方向键 → `model.slide()`；`moved` 为真才：加分、播音、**若作弊未开则 `spawn()`**、刷新视图、检查结束与 2048。
- `OVER`：`GAME OVER / SCORE n / PRESS SPACE`。空格重开。

- **输入走 `_unhandled_input` 的按键事件**（`is_action_pressed` 默认排除按键回声），所以**按住不放不会连发**，一次按下 = 一步——这是原作的手感。
- **结束判定**：`slide` 之后若 `not model.can_move()` → `OVER`。
- **达成 2048**：`model.largest() >= 2048` 且本局还没报过 → 飘一句 `2048!` 提示并置 `_announced_2048`，**不结束游戏**。
- **视图刷新**：`_refresh_board()` 遍历 16 个 `Panel`，按数值取缓存的 `StyleBoxFlat` 与文字（缓存见 §6），字号按**位数**分档。无值则用空格样式。
- **作弊**（`[`）：`_cheat_no_spawn` 取反；开启时 HUD 常驻 `NO SPAWN`；**每次开局复位为关**。
- 布局：`Board` 的尺寸由 16 个格子的 `custom_minimum_size` 决定（`4*tile + 3*gap`），代码只负责把它**居中**到场地（`(SIZE - board_size) / 2`）。

## 6. 配置 `twenty48.cfg`

**完整取值与注释以 `08-twenty48/twenty48.cfg` 为准**（唯一可信源）。分区职责：

| 分区 | 关键项 | 职责 |
| --- | --- | --- |
| `[board]` | `bg_color` `panel_color` `empty_color` `spawn_four_chance` `tile_size` `gap` `corner_radius` `font_sizes`（按位数分档的数组） | 配色、几何、字号档位 |
| `[tiles]` | `values`（递增数组）`colors`（同长度同序）`dark_text_color` `light_text_color` `dark_text_upto` | 数值→颜色映射；文字用深色还是浅色由 `dark_text_upto` 这条**规则**决定，不逐值列 |
| `[audio]` | `merge_tones`（数组） | **按 log2(数值) 索引**的合并音高，不够长时取最后一个 |
| `[hud]` | `font_size` `margin` | HUD 字号与边距 |

- **`values` 与 `colors` 必须等长**（`Game2048Settings` 校验并 `push_error`，不静默画错）；超出表尾的数值（如 8192）用**表尾那一条**的配色。
- 颜色以 6 位 hex 存，加载时 `Color.html` 解析。代码内**零调参魔法数**。

## 7. 只读叠加层（`game2048_debug.gd`，`class_name Game2048Debug`）

- **`P`（`debug_toggle`）**：棋盘下方一行读数——
  - `MOVES`（累计有效步数）、`EMPTY`（当前空格数）、`MAX`（最大块）；
  - **四个方向哪些还能走**：`L R U D` 四个字母，可走的画亮绿、走不动的画暗红（"我按了方向键怎么没反应"的答案）。
- ⚠️ 开关**必须"出去也重绘"**（`_draw` 的绘制命令会被画布缓存）——**照抄 `03-pacman/scripts/pacman_debug.gd` 的带 setter 写法**（DECISION_LOG 029）。
- 读数用一个**在调色板里不出现的亮青色**，方便用像素计数验证开关（`FF3FA4`）。

## 8. 程序化音频（`game2048_audio.gd`，`class_name Game2048Audio`）

启动时合成 PCM 到 `AudioStreamWAV`（22.05kHz / 16-bit / 单声道），`AudioStreamPlayer` 池播放。

| 事件 | 音色 | 触发 |
| --- | --- | --- |
| 滑动 | 方波 160Hz / 0.05s | 本步确实有位移 |
| 合并 | 方波短音，**音高取 `audio.merge_tones[log2(数值) - 1]`** | 发生合并 |
| 达成 2048 | 上行四音 | 首次出现 2048 |
| 结束 | 下行三音 | 无处可走 |
| 开局 | 方波 300Hz / 0.10s | 空格开局 |

合成 helper（方波 / 音阶 / 包络）与 01–07 同源，**后续可整体抽到 `plugins/`**（DECISION_LOG 015 备注，时机由用户定）。

## 11. 验收

### 可自动校验的（headless）

- `godot --headless --path . --import` 无 error / warning。
- 场景可加载、无脚本错误。
- 一次性断言脚本覆盖（**重点在纯逻辑模型上**，不依赖场景树）：
  - 合并规则：`2 2 2 2` 向左 → `4 4`（每块只合一次）；`2 2 4` 向左 → `4 4`；`4 4 4 4` 向左 → `8 8`；`2 4 2 4` 向左**不变**；
  - 四个方向的读取/写回顺序各自正确（同一局面四个方向的结果分别断言）；
  - `moved` 的判据：只有棋盘真变了才为真（"按了没反应"的局面 `moved == false`）；
  - `gained` 等于合并出的数值之和；
  - `spawn` 落在空格且只放在一个格、无空格时返回 -1、`four_chance` 的两个极端都只产生对应的值；
  - `can_move()`：满盘无相邻相等 → false；满盘但有一对相邻相等 → true；有空格 → true；
  - **8 个方向上的 `slide` 都不改变方块总数所蕴含的能量**（守恒检查：所有块的 log2 之和，加上本次 gained 的 log2 贡献，必须与走之前一致）——这是最能抓住合并实现错误的一条；
  - 状态机：开局两块、有效步才冒新块、作弊开启后不再冒新块、凑出 2048 只报一次且不结束、无路可走 → OVER、重开复位（分数 / 最大块 / 作弊）。
- 调试叠加层用**像素计数**证明关得掉（该颜色别处不出现）。
- 真实窗口让程序自存 `save_png` 后读图，确认标题 / 游玩（多色方块）/ 调试读数 / 结算画面。

### 已跑过的

- `godot --headless --path . --import`：无 error / warning，6 个 `Game2048*` / `Twenty48*` 全局类全部注册。
- 场景可加载、无脚本错误（与 02–07 同样只报既有的音频对象泄漏）。
- **断言套件 95 项全过**（连跑两遍一致）：
  - **合并规则逐条钉死**：`2 2 2 2 → 4 4`（不是 8）、`2 2 4 → 4 4`、`4 4 4 4 → 8 8`、`2 2 2 → 4 2`、**`4 4 8 → 8 8`（合并出来的 8 不再与后面的 8 合并）**、`2 4 2 4 → 不变`、`0 2 0 2 → 4`（先靠拢再合并）；
  - **四个方向**各自按同一块盘验过读/写顺序，纵向还验了"同列两块 2 向下合并到远端"；
  - **随机盘上的不变式（300 局）**：**质量守恒**（合并既不创生也不销毁数值）、**每行每列最终都贴着目的端**（不留下夹缝）、有效滑动不会凭空多出空格；
  - `moved` 判据、`gained` 与非空合并一致、`spawn` 落在空格（`four_chance` 取 0 / 1 的两个极端都验）、满盘时返回 -1；
  - `can_move`：满盘无相邻相等 → 死局；只差一对相等 → 仍有解；有空即能走；
  - 状态机：开局两块、空操作不计步也不冒块、作弊开启后不再冒块、**凑出 2048 只报一次且不结束**、死局 → OVER、重开复位（分数 / 步数 / 作弊 / 里程碑，且**最高分保留**）；
  - **调试读数的四方向可行性**与"按键真会发生什么"逐一比对，且**探测本身不扰动棋盘**；
  - 配置校验：`values` 与 `colors` 等长、数值表递增、字号随位数递减；音效非静音且各合并音互不相同。
- **调试叠加层可见性（像素计数）**：叠加层用调色板里不出现的亮青，**开=1503 / 关=0 / 再关=0**。
- **画面实拍**：真实窗口下让程序自存 `save_png` 后读图，确认标题 / 游玩（八种数字配色）/ 调试读数（含四方向红绿标记）/ 作弊常驻 `NO SPAWN` / 结算五态。

### 实拍与断言暴露并修掉的问题

- **提示文字在白底上看不见**：标题与提示原本用 `light_text_color`（近白），压在米白棋盘上等于没有。改为深色，并把**版式改成"提示条在棋盘下方、调试读数在棋盘上方"**——两侧都不再有文字压到方块上。棋盘尺寸随之收到 112px 以腾出底部那条空白带。
- **`offset_top` 是相对 anchor 的**：把 `offset_top = -118` 配在 `anchor_top = 0` 上，等于从**屏幕顶部**往上 118px，文字直接跑到画面外。锚在顶边就得用正的绝对偏移。
- **调试读数的方向字母叠在正文上**：我按"字符数 × 字号 × 0.72"估文字宽度，而 Press Start 2P 的步进约等于字号——估短了就把字母画到了正文里。改成向字体问真实宽度（`font.get_string_size`）。

### 关于断言的自我提醒

这一款的断言我**写错了四次期望值**（`up` 的期望写成了滑动前、`2 2 0 0` 向右当然能动、"顶部那一行的块不能下落"、以及 `_add_score` 之外直接改 `_score` 不会更新最高分），还有一条**不变式本身是错的**——"同方向滑两次是空操作"在 2048 里不成立：`2 2 2 2` 左滑得 `4 4`，再滑就该得 `8`，这正是原作规则。全部按"这情况下实际的合法行为是什么"重新推导后才通过（踩坑清单第 19 条）。

- 手感：是否要加滑动动画（当前无，瞬间就位）。
