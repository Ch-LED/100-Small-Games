# 00-hub — 策划案

## 定位

`00` 是项目本体：**启动器**。它不为任何单一玩法服务，而是 100 款游戏的统一入口——像手机桌面，把每一款游戏呈现为「图标 + 名字」的 app 入口，点击进入、返回原位。

## 用户与体验流程

1. 启动 → **标题画面**（logo / 游戏集标题 + 「开始」+ 全屏/窗口切换 + 退出）
2. 点「开始」→ **app 网格桌面**（多行图标，自动按窗口宽度换列）
3. 点击某款游戏 → 进入该游戏（整树切换，游戏独占画面）
4. 游戏内点「返回桌面」→ 回到网格，**滚动位置保持**，不回到标题

## 核心体验要素

- **分辨率自适应**：任意窗口尺寸 / 全屏，界面不裁切、不变形、不糊；容器铺满、按需换列。
- **app 感入口**：每款游戏一格，圆角图标 + 下方名字（中文展示名）；无图标时降级为占位块。
- **返回不丢位置**：从游戏回来直接落在桌面原滚动位置，而不是标题画面。
- **中性不抢戏**：hub 视觉克制、暗色打底，避免与各游戏争注意力；不在 hub 引入游戏专属 UI。

## 视觉方向

- 深色背景 + 高对比 app 图标格；标题画面可用项目 icon 作主 logo。
- 交互回馈：悬停高亮、点击有瞬时按压感（scale/alpha），手感统一且轻。
- 字体/字号随窗口自适应（固定 design 分辨率下用拉伸，必要时再收紧）。

## 验收标准

- [ ] 冷启动直接跑 `project.godot` 主场景即进标题画面。
- [ ] 任意拖拽窗口尺寸 / 切全屏，布局不错位、不裁切（demo 图标齐全可点）。
- [ ] 开始进入桌面，能看到 `99-demo` 的图标与中文名。
- [ ] 点 demo 进入其场景；点「返回桌面」回桌面且位置保持。
- [ ] 某游戏目录缺场景/缺 meta/缺图标时，其余游戏不受影响，该项正确降级。
- [ ] 进入 demo 后再次往返多次无报错、无内存叠积。

## 范围与非目标

- 不做：游戏内的通用 UI、收藏/搜索/历史、联网、主题系统。
- 允许未来演进：入场过渡动画、图标懒加载、按目录再分组——先进 TODO，不与首版耦合。
