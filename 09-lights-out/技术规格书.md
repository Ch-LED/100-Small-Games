### 3.1 棋盘与格子

- **位置一律不由代码计算**：`Board` 是 `GridContainer`（`columns = 5`，行列间距从 cfg 设入），25 个 `Panel` 按 row-major 挂在它下面，引擎负责排布。代码只设 `custom_minimum_size` 并**居中整块棋盘**。
- **一个格子就是一盏灯**：不需要额外的实体节点，也不做对象池，翻转只是换样式。
- **样式由三个布尔量决定**（亮 / 提示 / 光标），**按需缓存**（最多 8 种组合），不预先铺开成 8 份手写配置：
  - 底色：亮 = `on_color`，暗 = `off_color`
  - 描边：提示优先 `hint_color`，否则光标 `cursor_color`，都没有则不描边
  - 圆角用 `StyleBoxFlat.set_corner_radius_all()`
- 布局（**沿用 08 已验证的版式**）：棋盘居中，**调试读数在棋盘上方**、**提示条在棋盘下方**——两侧都不会有文字压到格子上。
- 界面以外的访问一律 `@onready var _x: Type = $Path`（CONSTITUTION 五）。

## 4. 数据模型（`grid_model.gd`，`class_name LightsOutGrid`）

**纯逻辑，`extends RefCounted`**，状态就是一个 **25 位整数** `bits`（1 = 亮）。不碰场景树，因此求解器与规则都能被**直接断言**。

- `SIZE := 5`、`CELLS := 25`、`SOLVED := 0`。
- **`press_mask(row, col) -> int`（静态）**：一次按下会翻转哪些位——**自己 + 上下左右，越界忽略**。这是"按一下做什么"的**唯一来源**，`press()` 与求解器都走它。
- `press(row, col)`：`bits ^= press_mask(row, col)`。**按两次等于没按**（异或自己的逆），这条性质直接来自实现，也被断言钉住。
- `get_cell` / `set_cell` / `lit_count()` / `is_solved()`。
- **`scramble(rng, press_count)`**：从 `SOLVED` 出发，**挑不重复的格子**按 `press_count` 次。
  - **不重复**是必要的：连按同一格会互相抵消，那样生成的局面会比预期简单（甚至回到全灭）。
  - 因为"按一下"就是自己的逆操作，**这样生成的局面必定可解**。
- **`optimal_solution() -> Array[int]`**：**追灯法**，返回**步数最少**的那组需要按的格子下标。
  1. 枚举**第一行的 32 种按法**（`1 << SIZE`）；
  2. 对每种：先按第一行对应的格子，然后**逐行往下"追"**——只要上一行某列还亮着，就在下一行的同列按一下；
  3. 追到最后一行后，**若最后一行全灭则这是一组解**；
  4. 在所有的解里取**按的次数最少**的那组。
  - 全程在**位掩码副本**上算，不动 `bits`。
  - **⚠️ 5×5 标准 Lights Out 的系数矩阵秩为 23，不是满秩**（零空间 2 维 → 4 个"静默图案"）。两个后果：
    - **不是每个局面都有解**——所以 `scramble()` 那种"从全灭倒推"的生成方式是**必要的**，随手洒一盘会有相当概率是死局；
    - 可解的局面**通常有 4 组解**（互差一个静默图案，**步数各不相同**），所以 `optimal_solution()` 返回的是**最短的那组**，而不是"唯一解"。
  - 断言里两条都验了：**"按完必定全灭"**，以及**"恰好 4 个第一行按法可行、其中最短的步数与求解器给出的相同"**（后者用一份**独立重写的追灯**交叉验证，不是拿实现验自己）。

## 5. 对局（`game.gd`，`class_name LightsOutGame`）

状态机 `State { TITLE, PLAYING, SOLVED }`：

- `TITLE`：全灭的灯阵，`PRESS SPACE TO START`。
- `PLAYING`：接受输入 → `press()` → 计步 → 刷新 → 若 `is_solved()` 则 `SOLVED`。
- `SOLVED`：显示 `SOLVED IN n`，等 `solve_pause` 后 `_next_puzzle()`（`level += 1`、生成更难的题、回到 `PLAYING`）。
- **没有 `OVER`**：这是谜题，不是消耗类游戏（见策划案非目标）。

- **本题按了多少次**（`_presses`）在每次生成新题时清零；`_solved` 是本此运行累计解出的题数。
- **生成难度**：`press_count = min(start_presses + (level - 1) * presses_step, presses_cap)`。
- **输入**：
  - **鼠标**：走根 Control 的 `_gui_input`（位置已经是本控件的坐标系，见 DECISION_LOG 030），用点击位置反推是哪个格子（`Board.position` + 格子尺寸 + 间距）；落在格子上才计。
  - **键盘**：方向键 / WASD 走 `_unhandled_input` 的按键事件移动光标（单个方向键只动一格，按住不连发）；`fire`（空格）翻光标所在的灯。
  - **鼠标一动就把光标隐藏**，避免两套指示打架。

## 6. 配置 `lights-out.cfg`

**完整取值与注释以 `09-lights-out/lights-out.cfg` 为准**（唯一可信源）。分区职责：

| 分区 | 关键项 | 职责 |
| --- | --- | --- |
| `[board]` | `bg_color` `panel_color` `off_color` `on_color` `hint_color` `cursor_color` `hint_border` `cell_size` `gap` `corner_radius` | 配色、几何、描边宽度 |
| `[play]` | `start_presses` `presses_step` `presses_cap` `solve_pause` | 生成难度曲线与过关停顿 |
| `[audio]` | `press_tones`（5 元数组） | **每行一个音高**，从上到下由低到高 |
| `[hud]` | `font_size` `margin` | HUD 字号与边距 |

颜色以 6 位 hex 存，加载时 `Color.html` 解析。代码内**零调参魔法数**。

## 7. 只读叠加层（`lights_out_debug.gd`，`class_name LightsOutDebug`）

- **`P`（`debug_toggle`）**：棋盘上方一行读数——`PRESSES n`、`LIT m`、`OPTIMAL k`（最少几步能解）。**只报数字，不标位置**，所以是诊断而不是剧透。
- ⚠️ 开关**必须"出去也重绘"**（`_draw` 的绘制命令会被画布缓存）——**照抄 `03-pacman/scripts/pacman_debug.gd` 的带 setter 写法**（DECISION_LOG 029）。
- 读数用一种**调色板里不出现的亮青色**，便于像素计数验证开关。

## 8. 程序化音频（`lights_out_audio.gd`，`class_name LightsOutAudio`）

启动时合成 PCM 到 `AudioStreamWAV`（22.05kHz / 16-bit / 单声道），`AudioStreamPlayer` 池播放。

| 事件 | 音色 | 触发 |
| --- | --- | --- |
| 按下 | 方波 0.06s，**音高取 `audio.press_tones[row]`** | 翻转一次 |
| 过关 | 上行四音 | 全灭 |
| 新题 | 方波 300Hz / 0.10s | 生成新题 |

合成 helper（方波 / 音阶 / 包络）与 01–08 同源，**后续可整体抽到 `plugins/`**（DECISION_LOG 015 备注，时机由用户定）。

## 9. 输入

复用项目级 `[input]`（`project.godot` 已定义，本作无需新增）：`wasd_up/down/left/right`、`arrow_up/down/left/right`、`fire`（空格）、`debug_toggle`（`P`）、`cheat_toggle`（`[`）、`ui_cancel`（Esc）。

- **空格在本作的含义是"翻光标所在的灯"**（而不是"重开"）——本题没有"重开"的概念（见策划案）。
- 鼠标只在 `_gui_input` 里处理按下，用于直接点灯。

## 11. 验收

### 可自动校验的（headless）

- `godot --headless --path . --import` 无 error / warning。
- 场景可加载、无脚本错误。
- 一次性断言脚本覆盖（**重点在纯逻辑模型与求解器上**）：
  - **翻转掩码**：中心格翻 5 盏、角格翻 3 盏、边格翻 4 盏（逐个数出来）；**按两次回到原状**（对全部 25 格逐一验）；
  - 越界忽略：四角与四边按下时不越界、不误翻；
  - `scramble` 生成的局面**灯数不为 0**（不会一开局就是全灭）、**必定可解**（用求解器解它，按完必全灭）；
  - **求解器**：对 200 局随机盘，`optimal_solution()` **非空**、按下它之后**必定全灭**、且**步数不超过 `lit_count()`**（粗上界）；再验"按解里的格子顺序任意打乱都得到同一结果"（异或交换律）；
  - **唯一性**：对 200 局随机盘，枚举第一行的 32 种按法，**恰好只有一种能让最后一行全灭**——这是 5×5 满秩的直接体现；
  - `optimal_solution()` **不改变 `bits`**（在副本上算）；
  - `lit_count` / `is_solved` 与逐格读取一致；
  - 状态机：开局全灭、按空格生成一题、过关进 `SOLVED`、停顿后 `level` 加一并生成更难的题、**生成难度按曲线递增且封顶**、`_presses` 换题清零而 `_solved` 累计；
  - **作弊提示与求解器一致**：`[` 打开时标记的格子集合 == `optimal_solution()`。
- 调试叠加层用**像素计数**证明关得掉（该颜色别处不出现）。
- 真实窗口让程序自存 `save_png` 后读图，确认标题 / 游玩（暗亮分明）/ 键盘光标 / 作弊提示描边 / 过关五态。

### 已跑过的

- `godot --headless --path . --import`：无 error / warning，6 个 `LightsOut*` 全局类全部注册。
- 场景可加载、无脚本错误（与 02–08 同样只报既有的音频对象泄漏）。
- **断言套件 55 项全过**（连跑两遍一致）：
  - **翻转规则**：中心格翻 5 盏、角格翻 3 盏、边格翻 4 盏（逐个数出来）；**25 个格子各自连按两次都回到原状**；越界按下什么都不做（不环绕）；
  - `scramble`：**从不给出已经全灭的盘**、**盘盘都有解**（用求解器解它，按完必全灭）、12 次按下能产生多样的局面（验证"不重复格子"这条确实生效）；
  - **求解器（200 局）**：永远解得出来、**不解空**、**不扰动被问的那盘**、**按完必定全灭**、**解里没有任何一步是多余的**（逐一删掉一步，都必须不再成立）；

  - **4 个解的存在**本身也验了（对应"秩 23、零空间 2 维"）；
  - 点击映射：25 个格心都能映回自己、格子缝里与棋盘外都是"无格"；
  - 状态机：开局全灭、空格生成一题、按满后进 `SOLVED`、`_next_puzzle` 后 `level` 加一且**生成按次按曲线递增并封顶**、`_presses` 换题清零而 `_solved` 累计、**`[` 标记的格子集合与求解器给出的完全一致**、关闭后标记清空、重开复位；
  - 音效非静音且各行音高互不相同。
- **调试叠加层可见性（像素计数）**：调试色在游戏里别处不出现，**开=1583 / 关=0 / 再关=0**。

### 断言与实拍暴露并修掉的问题

- **⚠️ 我把这道题的数学记错了**：规格书与策划案初稿都写着"5×5 的系数矩阵满秩、每局恰好唯一解"。**这是错的**——标准 5×5 Lights Out 的矩阵**秩为 23**（零空间 2 维 → 4 个"静默图案"）。两个后果都被断言直接顶了出来：
  1. **不是每个局面都有解** —— 所以"从全灭倒推"的生成方式不是锦上添花，而是**必需**的（随手洒一盘有相当概率是死局）；
  2. 可解局面**通常有 4 组解**（步数各不相同）——所以作弊键取的是**最短**的那组，而不是"唯一解"。
  - 实现本来就是对的（`optimal_solution()` 遍历所有可行第一行取最短），**错的是我的说法和断言**。文档已订正，断言也改成"恰好 4 个可行第一行、最短那个与求解器一致"。
- 另外两处是**我断言里的期望值写错**：难度曲线的取样关卡选得太低（第 5 关还没到上限就断言已封顶）、以及"按一下唯一亮着的那盏就能清盘"（按下去会**点亮它的邻居**，当然不会清盘——改成把盘设成"恰好是一次按下的结果"再按回去）。

### 只有人能定的

- 观感：暗亮对比、圆角与间距、光标与提示描边的醒目程度。
- 难度：生成按次的曲线（`start_presses` / `presses_step` / `presses_cap`）。
- 听感：按下音高随行递增的辨识度。
