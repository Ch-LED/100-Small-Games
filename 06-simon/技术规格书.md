## 3. 结构模型（场景即架构，CONSTITUTION 五点五）

```
simon.tscn  (Simon, Control, game.gd)
├─ Background (ColorRect)
├─ Board (Node2D)
│   ├─ Hub (Polygon2D)                   中央暗色圆芯（代码填点）
│   ├─ PadUp    (scenes/pad.tscn 实例)   上 = 绿
│   ├─ PadRight (scenes/pad.tscn 实例)   右 = 红
│   ├─ PadDown  (scenes/pad.tscn 实例)   下 = 黄
│   └─ PadLeft  (scenes/pad.tscn 实例)   左 = 蓝
├─ Readout (Node2D, simon_overlay.gd)    只读叠加：状态读数（P）+ 序列圆点（[）
├─ Hud (Control, hud.gd)
│   ├─ RoundLabel / RoundValue
│   └─ BestLabel / BestValue
├─ Message (Control) > Label
└─ Audio (Node, simon_audio.gd)
```

- **四个扇区是结构**，写在场景里；每个扇区的角度区间、半径、颜色由 `game.gd` 在启动时参数化（`SimonPad.setup()`）。
- 节点访问一律 `@onready var _x: Type = $Path`（CONSTITUTION 五）。
- **扇区顺序即方向键顺序**：`PAD_UP/RIGHT/DOWN/LEFT = 0/1/2/3`，与场景里四个实例的排列一致——**新增/调换扇区只需改场景顺序 + 这个常量数组**，无需改逻辑。

## 4. 几何（`simon_board.gd`，`class_name SimonBoard`）

静态几何，`configure(outer_radius, inner_radius)` 在启动时算定：

- `CENTER = SIZE * 0.5`，`SIZE = (1280, 720)`。
- `OUTER` / `INNER` 半径（默认 236 / 96）。
- 扇区 `i` 的角度区间：**中心角 `=-90 + 90 * i`**（i=0 上、1 右、2 下、3 左），各张开 `90 - gap` 度，两侧各让 `gap/2`。
- `pad_at(point) -> int`：**按角度 + 半径判定点击落在哪个扇区**，落在芯里或圆外返回 `-1`。这是鼠标输入的唯一判据（不引入碰撞体：扇区判定是纯几何，用物理体反而是绕远）。
- `pad_polygon(index, segments)`：生成环形扇区的多边形点（外弧正向 + 内弧反向）。

## 5. 扇区（`simon_pad.gd`，`class_name SimonPad`）

- 场景：`Pad`(Node2D) > `Face`(Polygon2D)。
- `setup(pad_index, color, dim_amount, segments)`：用 `SimonBoard.pad_polygon()` 算好多边形填进 `Face`，并记下两种颜色——**`dim = color.darkened(dim_amount)`、`lit = color`**。
  - ⚠️ **不要用"亮起态提亮"的模型**：`Color.lightened()` 是把颜色往白里插值，红色会变成粉色，看起来是"褪色"而不是"点亮"。压暗未激活态、亮起用原色，才是"灯没亮/灯亮了"的读法。
- `set_lit(on)`：切换 `Face.color`。**只改颜色，不改尺寸**——亮起要一眼可见但不跳动。
- 点击判定不放这里：`SimonBoard.pad_at()` 用同一套（角度 + 半径）几何，避免"画的是一个形状、点的是另一个形状"（本仓库在 05-asteroids 上踩过这类不一致，见 DECISION_LOG 027）。

## 6. 配置 `simon.cfg`

**完整取值与注释以 `06-simon/simon.cfg` 为准**（唯一可信源）。分区职责：

| 分区 | 关键项 | 职责 |
| --- | --- | --- |
| `[field]` | `bg_color` `hub_color` `pad_colors`（4 元数组）`dim_amount` `outer_radius` `inner_radius` `gap_deg` `segments` | 配色、半径、扇区间隙与弧线精细度 |
| `[play]` | `base_step` `step_decay` `min_step` `flash_ratio` `start_length` `input_flash` `fail_pause` | 播放节奏、按键反馈时长与回合长度 |
| `[hud]` | `font_size` `margin` | HUD 字号与边距 |
| `[overlay]` | `dot_size` `dot_gap` `dot_y_margin` `state_font_size` `state_x` `state_y` | 序列圆点与状态读数的位置/大小（读数放在 HUD 之下、圆盘之上，避免相撞） |

`pad_colors` 是 4 元数组，**按 `PAD_UP/RIGHT/DOWN/LEFT` 的顺序**读入。颜色以 6 位 hex 存，加载时 `Color.html` 解析。代码内**零调参魔法数**。

## 7. 对局（`game.gd`，`class_name SimonGame`）

状态机 `State { TITLE, PLAYBACK, INPUT, FAILED, OVER }`：

- `TITLE`：圆盘静止，显示标题与说明，空格开局。
- `PLAYBACK`：按 `_playback_index` 逐个亮起序列；每步的**亮起时长 = `step * flash_ratio`**，其余为间隔。播完转 `INPUT`。
- `INPUT`：接受玩家输入。
  - 按对 → 亮一下 + 响对应音调；`_input_index` 前进一步。
  - **整段按对** → `round += 1`、序列 `append(随机扇区)`、进 `ROUND_CLEAR`。
  - **按错** → `FAILED`。
- `ROUND_CLEAR`：**过关与下一段播放之间的那口气**（`round_pause`，默认 0.9s），横幅闪一句 `ROUND n`。
  - ⚠️ **这一段是必需的**：早先的实现是"按完最后一下立刻 `_begin_playback()`"，而 `_begin_playback()` 会 `_darken_pads()` ——**把玩家最后那一下的亮起直接掐掉**，紧接着新一轮就开播，手感上像被偷袭。
  - 因此 `ROUND_CLEAR` **刻意不碰灯**（不 `_darken_pads()`），让最后一次亮起**自己走完它的时长**；等 `round_pause` 到点再交给 `_begin_playback()`（那时才清盘并留一拍前奏）。
- `FAILED`：错误音、圆盘灭、等 `fail_pause` 后进 `OVER`。
- `OVER`：显示本局回合数与最高分，空格重开。

**序列**：`_sequence: Array[int]`，扇区索引 0..3。开局 `start_length` 步，每过一回合追加一步（追加的那一步在**进入 PLAYBACK 前**入列，所以玩家下一轮要复述的就是加长后的序列）。随机用 `RandomNumberGenerator`，避免连续三次同色（`_roll_step()` 里重掷，最多几次）。

**速度曲线**：`step = max(min_step, base_step - (round - 1) * step_decay)`。`round` 从 1 起算。

**计分**：`_score = round - 1`，即"成功复述过的整段序列数"；`_best` 在本次运行内取最大。**错一次即结束**（原作契约，见策划案非目标）。

**输入**：
- 键盘：`PAD_ACTIONS` 表把 `wasd_*` / `arrow_*` 映射到扇区索引；走 `_unhandled_input` 的按键事件（与 04-snake 同理：保按键顺序，不会把同帧两键塌成固定优先级）。
- **鼠标单击在标题页与结算页等同于空格**（开始 / 重开）：本作吃鼠标，而玩家是**用鼠标从 hub 点进来的**，鼠标已经在手里，不该再让他去够键盘。同一条规则见 `07-breakout` §6.2 与 `09-lights-out`。
- 鼠标：走**根 Control 的 `_gui_input`**，而不是 `_unhandled_input` 的鼠标事件。
  - 原因：`_gui_input` 的位置**已经是该 Control 自己的坐标系**，不用去推 `canvas_items + keep` 的拉伸变换到底作用在哪一层；`_unhandled_input` 里拿到的事件坐标属于哪一层空间则需要额外验证。**少一次推理就少一个错**。
  - 代价：所有 Control 子节点（`Hud`、各 `Label`、`Overlay`/`Message`）都必须 `mouse_filter = 2`（IGNORE），否则它们会先吃掉点击。场景里已逐个设好。

## 8. 只读叠加层（`simon_overlay.gd`，`class_name SimonOverlay`）

- **`[`（`cheat_toggle`）→ PEEK**：在底部把当前序列画成一排彩色圆点（按扇区颜色）。记忆游戏最自然的作弊/自测方式。
- **`P`（`debug_toggle`）→ 状态读数**：角落一行文字 `PHASE / STEP i-n / ROUND / STEP xxms`。**不含序列内容**，是纯诊断。
- 两个开关互不影响；数据由控制器每帧推入（`sequence` / `phase_name` / 进度 / 时长）。
- ⚠️ **两个开关都必须"出去也重绘"**：`_draw` 的绘制命令会被画布缓存，只在开启时请求重绘的话，**关掉后最后一帧会留在屏幕上**。这里**直接采用 `03-pacman/scripts/pacman_debug.gd` 已有的写法**（带 setter 的开关，值一变即 `queue_redraw()`），见 DECISION_LOG 029。

## 9. 程序化音频（`simon_audio.gd`，`class_name SimonAudio`）

启动时合成 PCM 到 `AudioStreamWAV`（22.05kHz / 16-bit / 单声道），`AudioStreamPlayer` 池播放。

| 事件 | 音色 | 触发 |
| --- | --- | --- |
| 四个音调 | C 大调 `C4 261.63 / E4 329.63 / G4 392.00 / C5 523.25`，方波 0.22s | 播放序列与玩家按键 |
| 错误 | 下行噪声爆响 + 下行音，约 0.5s | 按错 |
| 开局 | 上行三音 | 空格开局 |

- 音调**与扇区一一对应**（索引 0..3），方波带快起音/尾部释放包络。
- 合成 helper（方波 / 加噪 / 包络）与 01–05 同源，**后续可整体抽到 `plugins/`**（DECISION_LOG 015 备注，时机由用户定）。

### 10.1 超级作弊 `]`（`super_cheat_toggle`）——机器替你按

- **机制**：`_tick_auto_play()` **只在 `State.INPUT` 里跑**（播放阶段与回合交接都不插嘴），每 `[play] auto_step`（0.35s）按一次 `_sequence[_input_index]`，按完即停。**走的是 `_press_pad()`**——键盘、鼠标同一条路——所以亮灯、音调、回合交接与玩家亲手按的完全一致。
  - **节奏**是有意的：0.35s 慢到能看清"是它在按"，不是故障闪烁。
- **表现**：**圆盘中心（hub）变绿**。这是唯一不会与"某块扇区亮起"看混的位置；另配一句 `AUTO PLAY ON/OFF` 提示。
- **复位**：`_enter_title()` 与 `_start_run()` 都走 `_set_super_cheat(false)`。
- **实测（帧驱动断言脚本，跑完即删，15 项全过）**：开着且**完全不操作**，3000 帧内推进到**第 6 回合**；关着同样帧数**停在第 1 回合**；中心颜色开关双向正确；**新一局必然是关的**。

- 场景可加载、无脚本错误。
- 一次性断言脚本覆盖：`pad_at()` 的四象限判定与边界（圆心/圆外/缝里）、扇区多边形的点数与闭合、速度曲线的单调递减与下限封顶、序列每次恰好加长一步且取值合法、计分公式、读序列推进（按对前进一步、按错进 FAILED、整段按对则回合 +1）、`P`/`[` 两开关的可见性（关掉后叠加层像素数下降）、四个音调与错误音的缓冲非静音。
- 真实窗口让程序自存 `save_png` 后读图，确认标题 / 播放 / 玩家回合 / 结算四态画面，以及 PEEK 圆点、亮起的扇区。

### 已跑过的

- `godot --headless --path . --import`：无 error / warning，7 个 `Simon*` 全局类全部注册。
- 场景可加载、无脚本错误（与 02–05 同样只报既有的音频对象泄漏）。
- **断言套件 61 项全过**：四象限角度判定（含 atan2 在 ±180 处翻转的那条缝，左右两侧都要判成同一个扇区）、缝里与芯里与圆外都返回"无扇区"、360° 扫描下四个扇区都可达、扇区多边形点数与内外半径、**"画出来的弧必须落回它自己的可点范围"**（把"画的和判的是同一个形状"钉成断言）、序列每次恰好加长一步且取值合法、**永不连续三次同色**、回合与序列长度推进、按错进 FAILED、结算的 best = 实际清过的条数、重开保留 best、越界点击被忽略、速度曲线逐回合不升且在 `min_step` 封顶、四个音调互不相同且都不静音不削波、错误音与开局音可闻。

- **画面实拍**：真实窗口下让程序自存 `save_png` 后读图，确认标题 / 玩家回合（一块扇区亮起、其余压暗）/ PEEK 圆点 / 状态读数 / 结算五态。

### 实拍暴露并修掉的问题

- **亮起的表现反了**：原本用 `lightened(0.55)` 表示亮起，红色被冲成粉色，看着像"褪色"而不是"点亮"。改为**未激活压暗 62%、亮起用原色**，对比强且保住色相。
- **状态读数压住了 HUD**：读数原本画在左上角 `y≈20`，正好和 HUD 的 `ROUND` 重叠。改到 `y=72`（HUD 之下、圆盘之上），并把位置拆成 `state_x` / `state_y` 两个 cfg 项。

### 修过的

- **过关到下一段播放之间没有留白**（用户实机发现）：`_complete_round()` 原先直接调 `_begin_playback()`，后者会 `_darken_pads()`，**把玩家最后那一下的亮起当场掐掉**，新一轮紧接着就开播。已加 `ROUND_CLEAR` 状态（`round_pause` 默认 0.9s），**期间刻意不碰灯**，让最后一次亮起走完，横幅同时闪 `ROUND n`。断言里专门验了"暂停期间仍有灯亮着"与"交给播放时盘面已暗"这两件事。

### 只有人能定的

- 听感：四个音调是否好分辨、错误音是否刺耳。
- 手感：播放节奏（`base_step 0.62` / `step_decay 0.018` / `min_step 0.24`）、过关留白（`round_pause 0.9`）与鼠标点击的判定宽容度（`gap_deg 5` 决定缝有多宽）。
